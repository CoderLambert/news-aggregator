# NewsHub开发方案与任务文档

**Agent 调度、本地源码开发与交付**：先读[本地开发与任务调度指南](AGENT-LOCAL-DEVELOPMENT.md)。本文其余部分是功能计划的存放与索引约定，不代替当前派发任务或根规则的验收/授权边界。

本仓库后续使用 `superpowers:writing-plans` 或整理功能开发计划时，统一保存到 `docs/development/任务计划/<feature-key>/`，按功能组织。此路径为用户指定，覆盖技能默认的 `docs/superpowers/plans/` 保存位置；不修改全局技能包。

进入[任务计划索引](任务计划/README.md)，当前功能为[RSS Discovery V1](任务计划/rss-discovery-v1/README.md)。已有工程标准等文档保持原位置，本次不整理无关历史材料。

每个功能目录包含：

- `README.md`：功能入口、当前阶段和阅读顺序。
- `完整方案.md`：产品目标、边界、架构及完整验收条件。
- `任务执行计划.md`：任务总览、依赖、顺序、文件所有者和验收映射。
- `开发合同.md`：被多个任务引用的接口、数据结构和执行前提；简单功能可并入总览。
- `tasks/<module>/`：按功能模块组织的任务卡，一项任务一份文档；保留已有任务ID，需要细拆才加子编号。

任务卡按当前功能需要写清做什么、怎么做、涉及文件、依赖、输入输出、用户验收及回退。当前RSS MVP先做功能、由用户逐项测试，自动化测试后补，不把大测试计划作为开发前置。任务以可验证结果划分，可以有前置依赖；不要机械地按文件拆成零碎任务。

总览只列索引和状态，不重复任务正文。旧路径迁移后保留跳转；测试正式消费的fixture留在代码/测试目录，不放进CI忽略的docs目录。证据与运维记录有实际执行结果时再补，不为每个任务预建空报告。

方案、拆分完成、实现、测试、用户验收是不同状态。创建计划不授权产品开发、提交、合并、真实服务调用或部署。
