## 原因与恢复范围

旧源码仍保存在 `uat-20261020/build-translation-redis-20261020-151802`，但没有进入可达 Git 提交。当前 9527 的 e44da7b 应用镜像缺少 Redis Python 依赖、transport 模块及 worker/SSE 接线；只有健康的 Redis 容器及 URL 环境配置，不能证明业务已使用 Redis。运行代码与本次基线的旧翻译 views/service 文件哈希一致。

恢复旧 transport 的有界内存缓冲、Redis Streams 发布和命名 SSE 事件；只移植翻译传输差异，保留当前多模型配置、默认绑定、私有结果、内容与凭据 fencing。没有移植旧稿中的模型限制和公共译文发布逻辑。

- 模型 delta → 25 ms / 4 KiB 合批 → Redis → SSE → 原有 Streamdown；生成循环不查询数据库，也不逐段写 progress。
- 任务创建、只读 HTTP 鉴权、每段模型发送标记、后台权限/lease 校验及最终结果仍由数据库负责。后台控制校验每秒一次，与 delta 数量及观察页面数无关；这不是全面取消数据库权限校验。
- 独立页面各自 XREAD，不用 consumer group；owner/task/generation 隔离、run token fencing、2 秒控制新鲜度、短 TTL 和有限缓冲。
- 终态成功在结果事务提交后发布。Redis 断连、EOF、过期或缺口均不生成成功状态，不自动重新请求模型。
- queued 尚无 Redis publisher 时只等待 Redis；已建立的观察循环不回查数据库。连接轮换由新的 HTTP 请求重新鉴权。
- 前端有效 Redis 回放重置连续失败额度，避免长任务耗尽重连；无 cursor 的 queued 快照不能重置额度，持续故障仍停止并提示只读恢复。失联时不再误报“等待模型响应”。
