## 测试发现与修复

1. 预览把已有订阅算成无效条目：新用例先失败，再把无效计数改为明确 status=invalid；已有订阅保持未选中、禁用，复用渠道仍可选。旧预览文案断言同步新版计数，并未删除行为断言。
2. 同步/单次领取失去恢复优先级：未知配置回归中恢复次数被普通收敛操作挤占。默认入口先尝试恢复、没有实际可领取恢复工作时再尝试普通任务。审阅进一步发现的“到期恢复受 Retry-After 阻挡时其他站点停工”已用专门用例复现 FAIL 再确认 PASS。
3. 取消最后一个意向时，迟到 create 的清理被10秒退避延后：现在正向观察到迟到创建且当前 desired_enabled=false 时立即安排只读核对，再执行当前禁用策略；不重发 create。原实际 worker 取消回归已通过，仍断言个人订阅不存在、create仅1次、远端 feed 最终 disabled。
4. 新三用户测试复现恢复队列为空时清掉轮转记忆，导致同一用户再次拿走刚空的槽。控制调度保留跨队列轮转，按全局活跃用户定期清理历史提示；竞争判断只看当前可排队用户，历史用户不阻止单用户借满4槽。
5. 共享协议相关旧 fixture 改为设置真实物理 root，而非只改 follower 标签；增强“follower被标失败但物理结果仍未知时必须409”的负向断言。租约回归模拟真实 _inflight 时钟及数据库 lease，保留不重复创建和独立读槽断言。

## 新增槽位和交互证明

- 4个实际网络 future 运行；其中一个完成后，其他请求仍阻塞时补入新任务。
- 双用户竞争各获2槽；三用户轮转跨 tick 保持。
- 单一用户可借满4槽，历史上已无队列的其他用户不构成竞争。
- 同一站点最多1个真实请求，同时继续处理另一个站点。
- 4个注册槽满时仍有1个核对槽，核对请求 reconcile=true。
- 没有文章同步器时，仍先接纳导入再执行控制 tick。
- 暂停、继续和取消剩余的 PATCH 均携带 viewer；取消需确认且保留已经成功的订阅。

均为受控 fake engine/线程 gate 与组件级测试，不是生产网络、浏览器 UAT、压力或多副本测试。
