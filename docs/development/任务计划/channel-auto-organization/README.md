# 新订阅自动整理与分组操作改进

在既有 owner 隔离、人工优先和可撤销整理合同上，个人分类现扩展为严格两级结构：

`根分类 → 子分组 → 频道订阅`

[实施计划与接口合同](implementation.md)包含原 AG-04.1、AG-05.1、AG-06.1、AG-07.1 及后续两级层级扩展；[本地验收指南](local-acceptance-20261023.md)保留历史候选事实并列出当前层级候选的检查项。

当前状态：层级候选基于主工作树实现并进行本地合成验证；尚未取得用户对这一行为变更的体验确认。历史 `d93beac118be31767097e251f6447edcc59be87c` 验收和 #21/#22 记录只证明当时的平面分组候选，不能作为本次层级候选的验收证据。未获明确请求不推送、不建 PR、不启动 CI。

验收时重点查看：

1. 首页阅读范围和频道卡片统一显示“根分类 / 子分组”；根分类只负责展开，不是聚合阅读范围。
2. 分组管理的两栏树支持根分类与子分组的创建、重命名、移动和删除；子分组移动后成员关系保持不变。
3. 智能整理分为“整理层级”和“整理频道”；任何 AI 层级移动或新根/子路径都必须先预览、勾选并确认。
4. 新订阅可靠规则可加入已有子分组；AI 建议和首个根/子路径保持待确认，未确认时不写层级或成员关系。
5. OPML 显示并匹配完整根/子路径；新子分组必须显式选择已有根分类。自动整理历史可安全撤销，后续人工操作保留。

后台 AI 需用户另行明确开启并绑定本人模型，AI 结果均需确认。离线测试与合成数据预览只支撑本地候选验收；不代表真实模型、生产、部署或线上回滚通过。

兼容边界：旧 topics 编辑器仍是明确标记的次要入口；频道成员、读取偏好、RSS 操作和旧绑定继续只保存子分组数字 ID。`/channels/manual` 已重定向到统一频道目录，不再维护第二套平面分组页面。
