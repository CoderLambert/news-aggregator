## 对“为什么反复做”的更准确解释

1. 旧成果留在未提交工作树和持久补丁，没有成为当前分支/main 的代码，因此从当前提交重新构建不会自动包含它。
2. 本轮修改 AI/RSS 界面时，从缺少这些前端改动的工作树构建并替换本地静态入口，旧体验没有随之前端构建保留。这是集成交付遗漏，不是用户记错。
3. 我没有先找到并逐项对照持久补丁，又将翻译入口做成独立面板、费用确认及纯文本进度，走回了旧验收已经排除的交互。这是本轮重复劳动的直接原因。
4. 补丁、分支提交、旧测试结果和当前运行版本必须分别记录；不能仅凭工作树名称或镜像运行，推断其前端源码已合并。
