## 1. 统一约定

| 范围 | 必须保持的行为 | 不应再次出现 |
|---|---|---|
| 配置入口 | `/settings/ai` 集中管理连接、模型验证、默认用途；复用 shadcn/ui，服务商/模型支持名称或 ID 搜索 | 在阅读页、小闻、翻译和研究面板嵌入模型选择器或配置链接 |
| 默认模型 | 消费已保存的用途绑定；用途为 `inherit_default` 才继承个人默认 | 默选列表第一项、自动改用其他连接、暗中借用站点 Key |
| 问答 | 小闻直接使用 `article_qa` 的有效配置，未单独设置时按合同继承默认 | 已配置仍要求重新选模型，读取失败误报“没有配置” |
| 问题推荐 | 使用 `question_suggestions` 配置；打开只读缓存/免费模板，点击生成即明确提交 | 打开面板自动收费生成、模型/费用配置面板、名称与相同 ID 重复展示 |
| 全文翻译 | 使用 `full_translation` 配置，结果仅当前用户可见；有个人绑定时进入既有个人翻译路径 | 正文工具栏、错误重试或朗读入口重新调用旧版个人翻译围栏 |
| 深度研究 | 使用 `deep_research` 配置；需要必要文本、工具能力通过验证 | 默认模型工具能力不足仍启动研究、失败自动改选其他服务 |
| 使用记录 | `/settings/ai/usage` 独立分页；默认每页 20 条，统计与分页数据分别展示 | 在模型连接页重新嵌入无分页长表、只统计当前页、补造 Token |
| 费用与恢复 | 保留明确发送确认；读取配置、状态、历史和缓存不触发新推理 | 把“继续接收”变成新付费任务；关闭页面、EOF 或失联被当成完成 |

“直接使用默认模型”表示无需在使用场景重新配置，不等于打开页面即自动发送收费请求。未配置、失效或无权限时必须阻止新请求，并区分具体状态。

## 2. 配置合同和状态

### 2.1 五个用途

| task_kind | 作用 | 留空含义 |
|---|---|---|
| `default` | 个人全局默认 | 未设置默认模型 |
| `article_qa` | 文章问答 | 按服务端返回的 `inherit_default` 继承默认 |
| `full_translation` | 个人全文翻译 | 同上 |
| `deep_research` | 深度研究 | 同上，仍需研究能力满足要求 |
| `question_suggestions` | 推荐问题 | 同上 |

配置保存接口：`GET/PATCH /api/me/ai/task-preferences/`。PATCH 携带已有 `revision` 与五项 `{task_kind, model_config_id}`，保持既有版本校验；不能用客户端状态绕过 owner、CSRF、模型能力或授权检查。

模型名称、连接名称、服务商模型 ID 与内部 `model_config_id` 是不同字段。业务提交绑定内部配置 ID，不能把显示名称或服务商字符串作为配置 ID。

### 2.2 状态必须区分

| 状态 | 展示/动作 |
|---|---|
| 读取中 | 简短加载态，不提前说未配置 |
| `available` | 使用该用途绑定；有效配置下不展示配置入口 |
| `inherit_default` | 读取有效默认绑定，并满足当前业务所需能力 |
| 未设置/失效/未验证 | 阻止新请求；说明默认模型当前不可用，不偷偷切换 |
| 元数据读取失败 | 提示读取失败并允许重读，不当成用户忘记配置 |
| 任务结果未知 | 保留旧请求身份并核对/恢复，不能自动创建第二个任务 |
| 原任务已运行 | 恢复使用原任务快照；改变默认模型不替换原任务模型 |

配置页只列符合用途的已验证模型。读取或保存配置、列出服务商/模型、搜索过滤不会发出推理。连接可用、目录可读取、文本验证成功、工具验证成功、真实业务成功是不同证据。

| 小闻 | `components/NewsChatAssistant.tsx`、`hooks/useChat.ts` | 默认问答、无配置控件或费用勾选、点击即提交、读取失败可重试 |

| 全局研究 | `research/ResearchPanel.tsx`、`hooks/useResearch.ts` | 研究能力、按次授权、唯一恢复提示、原请求幂等身份 |
| 历史记录 | `pages/AIUsagePage.tsx`、`workspace/AIUsageSection.tsx`、`App.tsx` | 独立路由、分页、owner、未知 Token 保持未知 |

上述路径统一相对 `frontend/src/`，其中 `components/` 可按代码目录定位；`news-detail/`、`workspace/`、`research/`、`speech/` 均在 `components/` 下。

| 业务 | 现有接口 | 约束 |
|---|---|---|
| 问答 | `POST /api/news/{id}/chat/` | 保存模型绑定与显式发送；文章/译文版本及 owner |
| 推荐问题 | `/api/news/{id}/suggested-questions/` | 只读与显式生成按现有协议区分 |
| 创建个人翻译 | `POST /api/news/{id}/byok-translation/` | 复用现有 DTO，绑定模型 ID、请求身份、正文版本 |
| 翻译状态/观察 | `GET /api/me/ai/translations/{task_id}/`、`.../events/` | 只读，不派发新任务；EOF 不算成功 |
| 翻译取消/重试 | `POST .../{task_id}/cancel/`、`.../retry/` | 保留 generation/幂等/权限检查；新尝试需明确确认 |
| 研究 | `POST /api/research/`、会话 chat/stream/resume-queued/cancel 路径 | 继续使用现有 owner、模型快照和重放合同 |
| 使用记录 | `GET /api/me/ai/usage/?page=1&limit=20` | 用户范围汇总与分页，不暴露他人记录 |

旧 `POST /api/news/{id}/translate/` 仍承担必要兼容。`ai_execution.personal_clients_for_user()` 的过渡围栏不能因为页面报错就被删掉；应把已有个人配置的使用入口接到已授权的新执行路径。ChatGPT Subscription 是独立授权路径，不得被个人模型设置隐式接管。

## 4. 每次修改后的快速 check

### 4.1 不触发推理的人工检查

- [ ] 设置页已有连接、Key 状态、已验证模型和用途绑定仍在；没有重新填 Key 或重新选默认模型。
- [ ] 在至少两篇文章打开小闻：没有模型选择框/配置入口；直接使用已保存问答模型。
- [ ] 无推理检查：文章顶部“翻译为中文”可用，没有模型配置红条或独立底部面板；真正点击会提交推理，放到用户明确发起的业务验收。
- [ ] 正文工具栏只有必要操作，无额外费用勾选、模型设置链接、大段实现参数或模型下拉框；翻译时在正文内逐步排版。
- [ ] 研究面板使用已保存研究模型；恢复状态只展示一次，恢复期间不要求新请求的费用确认。
- [ ] 推荐问题打开仅读缓存/模板，不因打开面板调用服务商。
- [ ] 使用记录打开独立分页页；翻页不减少全量统计，未知 Token 不计成 0。
- [ ] 刷新原标签页和新开页面均正确；不能只检查刚构建后新开的标签页。

这些检查不需要新增模型费用，也不应为了截图创建新连接或修改真实默认配置。

### 4.2 有影响时才做的负例检查

采用现有模拟接口/隔离测试，不改真实账号来制造故障：读取失败不误报未配置；用途失效不回退站点 Key；研究工具未验证不启动；账号切换不显示旧用户数据；旧任务默认模型变化后不换模型；未知提交不重复发送；取消/EOF 不伪装成功。

只在用户明确发起业务请求时做真实翻译/问答/研究验收，记录实际服务商、模型、请求结果；不能把配置读取、能力探针或模拟成功写成真实业务成功。

## 6. 防止下一次重复开发的交付记录

以后开始修复前先查本文、已关联验收文档、实际分支/工作树/dirty 状态及运行挂载，再判断是否需要重写。同类问题先核对所有第 3 节入口，不能只搜索一个报错文字。

| 项目 | 每次交付必须记录 |
|---|---|
| 源码 | 工作树、分支、HEAD/base、未提交/未跟踪文件；授权提交后记录包含修复的真实 commit |
| Git | 已提交、已推送、已合并分别记录；未授权时明确未完成，不能只写“已完成” |
| 构建/运行 | 构建来源、静态入口或产物标识、实际挂载/版本、保留的上一版入口 |
| 验收 | 检查了哪些入口、哪些真实请求由用户执行、PASS/FAIL/NOT_RUN；不能沿用旧候选证据冒充当前 |
| 剩余问题 | 后端服务可用性、真实业务、未合入改动分别列出；不把 UI 消失当成后端修复 |
| 续接 | 后续会话阅读本目录 README 与本文；先找已有补丁再实现，避免在不同工作树重复做同一功能 |

必要的只读核对命令：

```sh
git branch --show-current

git status --short
git worktree list --porcelain
git diff -- frontend/src/pages/NewsDetail.tsx frontend/src/components/NewsChatAssistant.tsx frontend/src/components/news-detail/PrivateTranslationPanel.tsx

```

不要为找到旧成果而 reset、clean、prune 工作树或覆盖当前构建；不要读取/复制真实 .env、Key 或数据库。授权 Git 交付后应把对应变更完整纳入一个可审查范围；有 pending 改动时禁止从旧目录重新 build 覆盖验收版本。
