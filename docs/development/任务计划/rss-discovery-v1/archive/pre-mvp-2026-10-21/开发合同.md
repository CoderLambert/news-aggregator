## C01 输入、编译与稳定身份

新增 `backend/api/rss/directory_build.py` 的纯函数：

```python
compile_catalog(inputs: list[dict], *, previous_entries: list[dict], public_sources: list[dict]) -> dict
```

**已选输入：** [tidings-top200.opml](tasks/catalog/tidings-top200.opml)，本轮固定200条、14个原始分类；sha256=`642a56712e128fa37c8239845d33ea7c8c216b69cf9f9087924a6db208db9e04`。RSSD-01的inputs只有这一个外部来源，不做多目录选型或补源。实施时复制同字节输入到backend/api/rss/directory_data/tidings-top200.opml并校验hash；此后编译/CI读取该运行目录副本，不直接消费docs中的材料。

`inputs`每项携带 `source={id,commit,license,url}`、文件path、已读取的bytes、sha256、license_sha256、adapter_version。本次只适配锁定OPML，生成JSON，不联网、不读DB、不执行JS。`previous_entries`覆盖承担身份凭证的保留历史，不仅是活动快照；`public_sources`首次为[]，后续消费C03的records。

返回 `DirectoryCandidate={payload:bytes, checksum:str, input_versions:{seed:str, editorial:str, public:str}, report:dict}`。payload为确定排序的UTF-8 JSON；input_versions各值为对应受审输入的SHA-256。未提供公共投影时使用空记录的确定哈希，不用当前时间制造版本。report对200项逐项列出接入/受限/拒绝/重复及安全原因，不含凭据URL；不能用其他目录补数。OPML缺失的语言/简介保持未知。

v2外层固定为 `{schema_version:2, source:bundle_source, input_versions, entries:[...]}`；v1仍可读。entry保留现有字段，增量包含 `entry_id/identity_key/site_url/aliases/category_keys/primary_category/origins`。原14个分类保留在origin及tags；现有六个本地展示分类仅做筛选映射、不改名单。六分类key固定为 `ai/programming/technology/open_source/general_news/science`；未知语言保持空值，API用null，不猜测中文/英文。

Feed的identity_key为 `feed:<保守规范化HTTPS URL>`。主机大小写/默认端口可规范化，路径/查询语义不改，HTTP隔离而不升级。模板为独立kind，身份包含来源、路由与参数合同。跨来源同一Feed仅一代表，不能按标题/域名去重；不同参数Feed保留。旧ID只能继续对应相同kind+target；改URL需新key/ID。优先复用同目标最早有效历史代表，否则以 `uuid5(uuid5(ENTRY_NAMESPACE, 'directory-v2'), identity_key)` 生成UUID；ENTRY_NAMESPACE复用directory.py的既有常量。同ID多目标拒绝发布。URL规范化是离线语法处理，不能解析网关配置或DNS而改变编译结果。

旧seed-v1只保留兼容/回退，不合并进本次Top200以扩数。新增种子与来源锁位于 `backend/api/rss/directory_data/`；每个来源记录精确commit、path/hash、许可及许可hash、适配器版本，生成产物另记checksum。上游validated_at只进provenance，本地verified_at不由种子填写。准备阶段可隔离坏记录，发布阶段结构错误必须整体拒绝。沿用8 MiB、10,000条、100 collections上限；空产物拒绝，较上次减少超过20%需显式审阅。

## C02 快照、激活与回退

复用 `FeedDirectorySnapshot/FeedDirectoryEntry`，新增最小目录派生模型 `FeedDirectoryOrigin`、`DirectoryVerificationEvidence` 和单例 `FeedDirectoryState`；统一由RSSD-02.1维护迁移。Origin保存可单独过滤的来源字段及规范化检索字段，不能把撤回安全依赖放在无法独立过滤的合并JSON里。

State保存 `revision`、所选输入版本、`pinned_checksum`；snapshot仍是唯一active事实，不另存第二个可独立漂移的活动指针。revision在真实激活/回滚/固定状态变更时单调增加，用于防止A→B→A后的旧构建误获授权。迁移序号按实际graph生成，并保持 `api.models` 注册/重导出。

新增 `backend/api/rss/directory_publish.py`：

```python
directory_head() -> dict  # {checksum: str|None, revision: int}
publish_directory(candidate: dict, *, expected_head: dict, pin: bool = False) -> FeedDirectorySnapshot
rollback_directory(checksum: str, *, expected_head: dict) -> FeedDirectorySnapshot
```

在事务外解析/编译，在SQLite短写事务内重新比较expected_head、全部input_versions和当前公共资料指纹，再创建/复用快照并切active。CAS冲突返回 `directory_publish_conflict`；无变化返回原活动快照且不增revision。所有激活入口（含v1包装、管理命令、Worker）统一走此服务，保留 `import_snapshot(payload, *, expected_checksum)` 的旧调用兼容；兼容入口不得绕过身份、固定版本和激活校验。

新增 `backend/api/management/commands/rss_directory.py` 子命令 `inspect/preview/publish/rollback/unpin`：preview只校验并输出安全差异；publish要求输入及checksum和显式预期head；rollback指定保留checksum并固定版本；unpin只解除固定，不删除数据。禁止reset/清空或批量注册Feed。回退保留schema、历史身份、证据、文章及全部用户关系。

## C03 公共资料投影与后台维护

新增 `backend/api/rss/directory_public.py`：

```python
load_public_projection() -> dict  # {records: list[dict], input_version: str}
visible_directory_origins() -> QuerySet
rebuild_public_directory(*, expected_head: dict) -> dict  # DirectoryCandidate，不激活
```

records按每个Feed关联输出，包含identity_key/public_url、source_id、publication epoch/policy_version、白名单资料字段指纹、相关link/binding身份、可公开的name/description/site_url/language/category字段。资料指纹覆盖非版本化Source字段，不能假定编辑都会增加policy_version。只投影正式公开来源；采集/订阅资格另外复用 `services/channel_catalog.py:current_feed_links/subscription_status`，正文和标题预览仍经既有access/public_membership。

visible_directory_origins在数据库中排除失去公开权限、版本/字段变化的公共贡献；在关键词匹配、排序、分类/语言筛选、facets、计数和分页前执行。独立外部资料可保留，但只能凭其自身字段匹配；不继承撤回资料的名称、简介、健康、provenance或预览。回滚旧快照也必须重查。

新增 `backend/api/rss/directory_maintenance.py:maintain_directory(*, now:float)->dict`，由现有runtime循环调用，30秒检查一次本地输入；变化合并为一个在途构建。使用同进程的单个受控目录future，不占用control/sync的网络执行池，tick只检查/收割，不等待构建。失败退避30/60/120/300秒封顶；迟到或CAS失效结果丢弃，重新读取最新输入。构建失败不能退出sync或丢失heartbeat；进程退出有界释放自身future。

无变化不发布；从正常变更到可检索目标60秒，失败记录积压且旧目录可用，撤回立即由读取授权兜底。首次空目录可初始化；已有活动v2、显式固定回滚不能被启动/每日seed-v1导入覆盖。固定期间不自动发布新输入，直至显式解除或新发布。

## C04 查询、精选与核验证据

保留 `directory.py:search_directory`，委托新增directory_search；签名为：

```python
search_directory(q='', *, limit=20, cursor=None, mode='search', category='', language='', kind='') -> dict
select_featured(*, category: str, language: str, limit: int, cursor: str|None) -> dict
record_directory_evidence(*, identity_key: str, evidence: dict) -> None
read_directory_health(*, identity_key: str, context: dict) -> dict
```

三个后续函数分别在directory_featured/directory_evidence模块。省略mode/kind兼容旧搜索；新UI明确mode和kind=feed。非法枚举400；q≤200字符（规范化前后均检查）、≤10词项、每项≤5个审定同义展开；limit 1～50、默认20。NFKC/casefold在导入期物化，英文按词边界、中文连续子串，多词AND、单项同义OR；`AI`不能匹配email，%/_是文字。

匹配层级：精确名称/别名/URL/域名、名称前缀、分类/标签、名称子串、简介；尾序按编辑权重、规范名称、稳定ID确定。数据库过滤排序分页后只补当前页，不加载全表到Python。签名游标绑定checksum、完整条件和排序版本；跨版本/条件400 `directory_cursor_expired`。授权变化优先移除失权贡献，必要时要求重查，不能为游标完整性泄漏数据。

精选配置只能引用已选Top200内的条目；不因配额或核验失败到外部补源。`directory_data/featured-v1.json` 保存entry_id、主分类、weight、reason；≥24个不同Feed、六主分类各≥4，首屏至多12。编辑推荐与健康独立，过期不移出/重排。证据为unknown/ok/error/stale，成功超过7天变stale；低频不等于故障。证据绑定identity_key、来源类型/版本、checked_at UTC、environment_id、engine_version、policy_version及安全error_code；私人运行证据不公开。受信服务可记录，目录输入或公开HTTP不能伪造。

mode=featured的首个响应使用min(limit,12)，后续游标按实际发出的边界继续；新UI显式limit=12，关键词搜索显式limit=20。不能先请求默认20条后靠前端隐藏8条，造成“加载更多”漏项。

read_directory_health返回 `{status,checked_at,environment_id,engine_version,policy_version,error_code}`；无可公开证据时status=unknown，其余为null。editorial返回 `{featured:boolean,reason:string|null}`，不得以健康状态替代编辑配置。

## C05 目录HTTP与订阅合同

复用GET `/api/rss/directory/`，参数q/mode/category/language/kind/limit/cursor；新增GET `/api/rss/directory/{entry_id}/`。返回 `results/next_cursor/snapshot_version/facets`；详情返回一条相同DirectoryEntry。失效/不可见ID统一404。列表/详情/精选GET只读本地，不发网、不写任务/订阅，继续private,no-store。

DirectoryEntry保留 `id/name/description/language/region/tags/origin/kind/public_url/required_parameters/capability_requirements/verified_at/executable/subscribed/cached_articles`；增量包括site_url、category_keys/primary_category、aliases、editorial、health、availability、user_state、action、origins。未知值用null/unknown。cached_articles最多3条，只含id/title/publish_time，不查全文。facets只汇总当前可公开贡献，不携带私人关系计数。

availability为 `{can_submit:boolean,reason:string|null}`，由当前站点写权限、登录与来源政策决定；匿名仍可浏览并显示登录动作。user_state为 `{subscription:'not_subscribed'|'subscribed'|'pending',operation_id:string|null}`，operation_id仅属于当前用户。legacy verified_at只来自当前可公开的成功证据，其他为null；不能回填上游时间。facets固定为 `{categories:[{key,label,count}],languages:[{key,label,count}],kinds:[{key,label,count}]}`，计数为资料过滤后同identity去重结果，绝不使用订阅人数。

action判别联合：`directory_subscription{entry_id,snapshot_version}`、`public_channel_subscription{source_id}`、`requires_configuration{reason}`、`unavailable{reason}`。网站候选及直接Feed仍是既有选择，不伪装目录action。同URL已有自己的有效关系显示已订阅；否则公共action优先，多个合格公共Source按source_id升序选定并展示实际名称；专属公共来源失效不静默转个人路径。

RSS POST仍为 `/api/me/rss-subscriptions/`，三类选择恰一：feed_url、candidate_token、directory_entry_id；可带group_ids/category_id，只有目录选择可带directory_snapshot_version。新请求旧版本409 `directory_changed`。同用户同键已受理请求先核对持久意图并安全恢复，不能先解析失效目录而404或重发register；同键异payload409。比较规范化目标、原选择/版本、分组与个人分类的不可变请求凭据，恢复结果仍重查owner/ACL。201/202/重放200沿用，RSS operation查询继续actor-scoped。

公共POST仍为 `/api/me/channel-subscriptions/` 的 `{action:'subscribe',source_ids:[id]}`，仅单source增量接受可选group_ids/category_id；事务内校验有效公共资格、分组归属和分类，再原子保存新关系。重复订阅保留既有设置，后续修改用set_groups/set_category及版本合同；旧客户端省略新字段保持旧行为。响应仍是既有订阅列表，**没有operation_id**，不做连接轮询。

## C06 能力与前端合同

新增settings `RSS_DISCOVERY_V2_ENABLED=False`。当前api.ts严格校验features键集合，故不直接往features新增key；在capabilities响应增加可选顶层 `extensions.rss_discovery={enabled:boolean,reason:null|'discovery_disabled'}`，旧features集合不变。旧解析器忽略顶层扩展；新解析器遇到缺失/非法扩展只将新发现能力设false，保持原有能力可解析。FAIL_CLOSED_CAPABILITIES和新增 `useRssDiscoveryCapability()` 返回同样保守值；不得复写core CapabilityName/Reason来放宽既有安全校验。

能力开关控制新浏览界面；浏览可匿名，写操作仍受登录、accounts、PUBLIC_SITE_MODE与后端授权约束。未知能力关闭新界面并保留旧添加入口；功能开关不替代API权限。

新增types/rssDiscovery.ts定义DirectoryEntry/DirectoryPage/DirectoryAction/DirectorySelection/SubscriptionOutcome；服务rssDiscoveryApi.ts提供：

```typescript
searchRssDirectory(params: DirectorySearchParams, signal?: AbortSignal): Promise<DirectoryPage>
getRssDirectoryEntry(id: string, signal?: AbortSignal): Promise<DirectoryEntry>
```

新增rssDiscoveryKeys包含viewer:number|null及完整筛选，复用workspaceRequest；为保留机器错误码，增量扩展现有WorkspaceError为可选code，不建第二个HTTP客户端。对既有构造调用兼容，未知错误继续安全文案。SubscriptionOutcome为 `{kind:'rss',operation_id,state,subscription}` 或 `{kind:'public',subscription}`，后者由现有列表中取本次source的当前用户关系；不能把两条原始响应混成operation。

DiscoverPanel props为 `{viewer:number|null,mode:'page'|'dialog',onDone?,onClose?}`，复用现有个人分类/分组查询。page将q/category/language/kind写URL，dialog局部保存。关键词300ms防抖，IME组合期间0次半成品请求，回车立即；URL显式提交才远程发现，vue.js先本地搜索并提供显式网站查找。无扩展名Feed保留“尝试直接添加”确认。

复用queryRefresh.ts/refreshRssViews、channel/news/workspace查询键，补发现结果及添加记录失效。换号取消/隔离旧请求，不能只依赖前端abort判断写入失败；服务端已保存的任务继续在添加记录可查。登录恢复只保存安全搜索与ID，重新查权限；不把candidate_token、完整敏感URL、私人分组放入公开URL或持久存储。

任务卡命令均从**无真实.env、进程不含真实凭据的隔离checkout**根目录执行，使用已有Python 3.12/Node 22及锁文件，`python`指向该兼容venv；当前脏工作区不得照抄运行。在任何Django进程启动前显式将DJANGO_DB_PATH设为任务专用临时路径，不能因新worktree仍含受版本控制的db.sqlite3就误用它。pytest使用既有migrated_synthetic_db/copy_synthetic_db；迁移测试另建临时DB。环境不符记NOT_RUN/BLOCKED，不换宿主runtime、重装共享依赖或读取真实密钥。

## C08 验收证据与交接

任务实现完成须有当前候选SHA、base、目录checksum、命令/退出码、范围、原负例失败与修复后通过证据。人工验收逐步记录PASS/FAIL/未测；代码/离线/隔离真引擎/浏览器/生产分列。证据在执行后放功能目录的 `evidence/<candidate-sha>/`，机器消费的fixture/运行配置仍留代码/测试目录。

审阅状态、实施状态和证据状态分别记录；本轮所有卡均“待审阅/未实施/NOT_RUN”。存在必需FAIL或NOT_RUN时不能宣称完整验收。尚未授权Git提交/PR/合并/部署，任务卡提交步骤只在对应授权后执行。最终遵守Draft快检、Ready整PR全量merge-gate与精确SHA；修复后回Draft迭代，不以快检绿灯替代合并门禁。

任务执行计划.md是导航索引，任务卡才是完整工作定义。后续执行器应读取选中卡及所引合同；若自动提取器只支持单文件Task N格式，在获授权的执行阶段由这些卡生成临时汇编并映射稳定RSSD ID，不维护第二套正文，也不将只有链接的索引误当完整执行brief。
