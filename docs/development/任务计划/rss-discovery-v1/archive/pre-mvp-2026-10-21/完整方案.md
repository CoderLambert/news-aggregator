## 0. 结论与边界

在现有 RSS 架构上补齐“打开即有推荐 → 关键词找到频道 → 查看资料与可用状态 → 确认分组并订阅”的闭环。

采用**版本化本地频道目录 + 已发布公共来源的目录投影 + Miniflux 网站发现 + 原有订阅服务**。不复制 Folo 后端，不依赖其内部 API，不新建 RSS 解析器、网站正文提取器或全网爬虫，不增加独立搜索服务。

关键区别：

| 概念 | 含义 | 是否产生采集或公开权限 |
|---|---|---|
| 目录候选 | 可搜索的频道元数据 | 否 |
| 编辑精选 | 推荐给用户的目录条目 | 否；不等于公共发布 |
| 公共频道 | 经既有流程发布的 Source | 沿用当前公共成员与正文授权规则 |
| 个人订阅 | 当前用户的订阅关系 | 走现有授权、连接与采集流程 |
| RSSHub 模板 | 仍可能需要参数和网关能力的路由 | 否；不能冒充已可用 Feed |

当前 `recommendations.py` 的“用户推荐公共频道”是投稿/审核流程，不是本需求的推荐排序器。保留其名称、权限与实现，不再建第二套审核。

- `directory_http.py` 已补充个人订阅状态和最多三条有权读取的文章标题，但采用逐结果查询。
- `DiscoverDialog.tsx` 已区分关键词、网站、Feed 和 RSSHub 地址；分页当前只提示缩小搜索范围。
- `directory_data/README.md` 记录的种子包含 38 个 Plenary HTTPS Feed、2 个自编 Feed 和 1 个 RSSHub 模板；它明确不把元数据作为健康证据。
- 已存在网站发现、个人订阅、连接进度、OPML、公共投稿和审核机制，均不重做。

本次只依据代码和公开上游资料制定方案，没有访问生产数据库或验证生产频道在线率。[S1–S7]

## 1. 产品方案

### 1.1 目标用户与成功定义

用户不必先知道 RSS 地址，也能找到想读的频道；知道网站或 Feed 地址时，可以从同一入口完成添加。结果必须说明来源是什么、是否依赖第三方、是否验证过、当前是否已订阅，不能靠虚假预览或统计制造“丰富”。

V1 的成功不是“新增目录接口”，而是用户可以完成发现、选择、订阅和阅读跳转，且原有权限与采集行为不回归。

### 1.2 入口与页面

保留现有 `/channels` 管理页面和添加按钮。新增 `/channels/discover` 完整发现页；添加弹窗与完整页复用 `DiscoverPanel`，不能分别维护搜索逻辑。

完整页保存 `q/category/language/kind` 到 URL，支持刷新和浏览器前进后退。弹窗采用同一组件的紧凑模式，不污染宿主页面的筛选参数。

页面分为：统一搜索框、分类/语言筛选、默认精选或搜索结果、频道资料与订阅操作。提供“浏览全部频道”入口，不把关键词搜索限定为“我已订阅的频道”。

### 1.3 默认推荐

空输入时请求明确的 `mode=featured`，首屏展示最多 12 个条目，并可加载更多。分类固定为：AI、编程开发、科技资讯、开源/Linux、综合新闻、科学；数据用稳定英文 key，文案可以本地化。

默认按编辑权重和分类多样性排列。语言优先级可作为既定展示规则，但用户选择语言后必须严格过滤。推荐理由使用“编辑精选”“官方技术博客”“该分类精选”等可解释文案，不使用没有依据的“热门”。

六个目录主题使用 `ai/programming/technology/open_source/general_news/science`，与已有个人 `category_id/category_version`、私人 `group_ids` 分别保存。订阅确认继续展示现有个人分类和多选分组；目录主题不自动写入个人分类，也不调用AI分类。

已订阅条目可以显示“已订阅”，不得再次创建关系。V1 不做行为追踪型个性化，也不调用模型。

### 1.4 一个输入框，三条执行路径

| 输入 | 行为 |
|---|---|
| 频道名、中文/英文关键词、别名 | 本地目录搜索，不请求发布者或外部搜索平台 |
| 网站 URL / 域名 | 先呈现本地匹配；用户显式提交网站发现后，通过现有任务调用 Miniflux |
| 完整 Feed / rsshub 地址 | 进入既有确认与订阅流程；后端仍需校验，不能只靠前端后缀判断 |

中文输入组合期间不请求；普通关键词 300ms 防抖，回车立即搜索。URL 的远程发现不随键盘输入自动触发。像 `vue.js` 这样可能是名称也可能是域名的输入，保留本地搜索，并提供“在此网站查找 RSS”，不静默访问网络。

Miniflux 的 Discover 接口输入是网站 URL，返回该网站的 Feed 候选，不是全网关键词搜索。[S10]

### 1.5 结果卡片与详情

卡片提供名称、纯文本简介、网站域名、分类、语言、来源类型、当前用户订阅状态、明确的操作按钮。图标优先使用已有安全缓存，否则使用本地字母/默认图标，不引入任意 URL 图标代理。

详情补充 Feed 地址、数据来源与许可、核验时间/环境、最近真实文章时间，以及最多三条当前用户有权读取的文章标题。

没有文章就显示“暂无可用预览，订阅后获取”；没有核验记录就显示“尚未核验”。不为填满卡片实时抓文章，不从私人共享 binding 中取公共预览，不把摘要声明为全文。

### 1.6 状态与操作

| 维度/状态 | 展示与操作 |
|---|---|
| 目录候选，允许提交但未核验 | 先选择并确认分类/分组，再“验证并订阅”；验证沿用既有register流程 |
| 当前用户已经订阅 | “已订阅 / 查看频道” |
| 当前用户连接请求处理中 | “连接中 / 查看添加记录” |
| 最近核验失败 | 展示安全原因；允许时提供显式重试，不自动循环请求 |
| 核验过期 | 展示上次检查时间，不继续标“近期已验证” |
| RSSHub 模板缺参数 | “需要填写参数”；V1 不新增通用模板表单 |
| 网关未配置/能力不足/策略禁止 | 禁用对应动作并说明原因 |
| 未登录 | 可浏览公共目录；订阅时登录，回来恢复搜索与选中项 |

编辑精选、健康状态、是否允许提交、个人订阅状态是四个独立维度，不压缩成一个绿色 `ready`。

### 1.7 首版规模目标

这些是计划验收目标，不是当前已经完成的数字：

- 固定接入用户选定的Tidings Top200 OPML，200条逐项有处理结果；不从其他目录补数、不设中英文配额，也不因包含视频/播客就另找文章来源替换。当前不支持的地址/类型单独标明。
- 推荐与核验样本只能从这200条中产生；既有至少24个推荐、六个展示分类各至少4个的展示目标不用于重新选外部源。发行验收的成功核验证据仍标明时间与环境；若固定名单无法满足目标，报告差额供审阅，不擅自补源。
- 运行时健康条件不满足可以少展示，不能用未验证来源冒充已验证来源补数。
- 候选数不等于实时可用数；验收报告必须分别列出导入数、排除数、去重数、核验成功/失败/未核验数。

### 1.8 明确不在 V1 内

不做全网搜索、AI 推荐/向量检索、公开用户榜单、推荐订阅人数、自动同步个人订阅到公共目录、凭据型 Feed、新 RSSHub 路由开发、社交关注、视频/播客专用阅读体验或生产部署。已有相关功能不能因本次排除新开发而被删除。

## 2. 渠道数据方案

### 2.1 已选来源：只接入Tidings Top200

用户已确认首版新增外部目录使用[本地tidings-top200.opml](tasks/catalog/tidings-top200.opml)，对应[Tidings中文说明](https://github.com/fuxiaoai/tidings-rss/blob/main/README.zh-CN.md)中的精选200。**不重新选源，不引入Plenary补充，不从718全集补数，不设中文/英文各50条门槛。** 既有种子、用户订阅及已发布公共Source保留现有兼容/投影职责，不作为本任务扩充外部清单的理由。

本轮只读核对本地文件：35,983字节、200个不同xmlUrl、14个原始分类；与上游精确提交 `f9b54abf9dd3e7af2a1dda12bca06c8fe8b57d7b` 的 `opml/tidings-top200.opml` 逐字节相同。SHA-256为 `642a56712e128fa37c8239845d33ea7c8c216b69cf9f9087924a6db208db9e04`。这证明输入身份，不证明Feed当前可达或已完成订阅。[S12]

本地文件有194个HTTPS、6个HTTP地址，分类中含2个Videos和11个Podcasts条目。保留原始分类和名单逐项记账；沿用当前HTTPS/内容能力边界，不擅自升级协议或开发新播放器。受限/不支持项明确原因，不静默丢弃，也不另找来源补数。六个展示分类仅是本地筛选映射，不能反向改变已选名单。

RSSD-01只负责读取这份OPML、适配名称/Feed地址/站点/分类、生成稳定ID与目录产物，并记录导入结果。OPML没有的简介/语言等字段如实未知，不从全网抓取补齐。正式运行输入在实施时逐字节复制到 `backend/api/rss/directory_data/tidings-top200.opml` 并锁定hash，使行为输入进入现有CI范围；本轮保留用户原文件不改。

Tidings目录许可按其来源记录保留；既有其他来源许可继续原样保留，不能因本次改用Tidings而重标现有资料。目录许可不等于文章再分发授权。第三方RSSHub地址保持来源标识，不冒充原生或自动改为站点网关。

### 2.2 输入锁与可复现性

每个来源锁定：仓库、精确 commit、文件路径、SHA-256、许可文件/哈希、适配器版本、导入日期。生成输出另记 checksum；不能用输入 commit 冒充生成文件所在的 commit。

只处理声明式 JSON/OPML；复用既有受限 OPML 解析能力，不执行上游 JavaScript、RSSHub handler 或 Radar 脚本。优先已有依赖，不为目录转换安装另一套 Feed 解析器。

### 2.3 导入流水线

`用户选定的Top200 OPML → 字段适配 → 必要安全/格式检查 → 稳定身份与原分类映射 → 200项处理结果 → 严格校验 → 原子发布目录快照`。

准备阶段将坏记录隔离并输出原因；发布阶段只接受完整通过校验的产物，一条结构错误、checksum 不符或数据库失败均不替换现有活动快照。

沿用 8 MiB、10,000 条、100 个 collection 的上限。空快照拒绝；相对上次减少超过 20% 时必须人工确认差异。来源服务不可达或格式改变时继续使用上一版本，不回退为实时外部检索。

### 2.4 去重与身份

按照受支持的规范 Feed URL 去重，不按频道标题或网站域名合并。不同栏目、语言、查询参数不同的 Feed 要保留。

仅使用已有保守规范化规则：主机大小写和默认端口可以规范化；路径大小写、查询参数及其语义不得随意改变。沿用当前公开目录与订阅的HTTPS限制，HTTP条目隔离并报告，不原样发布、不擅自升级协议；重定向、跨域别名和尾斜杠等等价关系须有受控证据再批准。

同一条目来自多个目录时，保留全部 provenance。保留已有代表 `entry_id`；合并失效的旧选择返回可恢复错误，不按名称替换目标。ID 不得复用于另一个 Feed。

具体身份规则：导入时对照保留的历史快照建立 `entry_id → kind + canonical target` 校验。旧ID只可继续代表同一目标；同来源/key改URL必须更换key/ID，v1重新导入也不得覆盖此约束。新Feed优先复用同目标的历史代表，否则用独立v2命名空间与规范URL生成确定UUID；模板身份还须包含来源、路由及参数合同，不与Feed混合。历史同目标多ID选最早有效代表，其他ID失效后要求重选；历史同ID多目标视为冲突并拒绝发布。回滚和来源增删不能绕过校验；在持久身份保留机制明确前不清理承担身份凭证的历史快照。

**目录去重不授权合并、重绑或删除现有 FeedBinding、Source 和用户订阅。**

### 2.5 来源类型

分别记录发布者原生 Feed、明确的第三方转换/镜像、RSSHub 实例以及路由模板。仅凭 HTTPS 不能认定为原生来源；来源不确定标记 unknown。已有可信原生地址优先，不能未经验证把第三方 URL 改成站点自有网关。

### 2.6 核验不制造订阅

目录发布不创建 Source、FeedBinding、ChannelSubscription 或 register 操作。

已接入公共频道的运行证据可以复用，但仅对公共授权范围有效。未接入精选候选只在专用隔离 Miniflux **实例及数据库/网络资源**中执行显式、有界的真实核验；同生产实例内另建账户不足以隔离负载与出网风险。关闭正文抓取，不同步到业务文章库；结束后只清理该核验创建且身份已确认的资源。远端结果未知先对账，不能盲目再次创建。

关闭crawler不等于Miniflux不会下载/解析Feed或存储其中条目；验收限制实际响应体、出网范围、并发、总时长和资源用量，不声称CreateFeed支持任意条目数量上限。每个目标每轮只创建一次；超时记unknown并对账，不强行凑满24个成功结果。

隔离核验的结果注明环境和时间，不声称已经证明生产网络可达。上游 `validated_at` 只留在来源说明，不能填充 NewsHub 的可信 `verified_at`。

## 3. 技术架构

### 3.1 边界

- **目录层：** 复用 `FeedDirectorySnapshot / FeedDirectoryEntry`，负责本地元数据、精选配置和检索。
- **发现层：** 复用 `discovery.py / FeedOperation / EngineAdapter`，负责显式网站发现。
- **订阅层：** 复用现有 RSS 订阅与公共频道订阅服务，继续幂等、授权与任务状态检查。
- **采集层：** Miniflux 负责常规 Feed 获取与正文策略；RSSHub 只通过现有合格网关使用。
- **阅读层：** 继续通过当前文章成员与正文 ACL，目录可见不等于文章可读。

不会增加第二个全文引擎、账户系统或后台采集服务。[S6]

### 3.2 统一目录，而不是另建一套来源系统

扩展现有快照格式到 schema v2，继续读取 v1。构建器同时接收：锁定的外部目录、编辑精选元数据、已有默认来源元数据、已经正式发布的公共 Source 投影。

对同一 Feed 合并展示资料，但保留每个资料来源的原始字段与 provenance。既有 `Source/FeedBinding/ChannelSubscription` 仍是采集、身份和关系的事实来源，目录是可重建投影。公共投影至少保留source_id、publication epoch/policy_version、link/binding身份和资料贡献；独立外部目录资料不能被同URL公共来源不可逆地覆盖。

Source资料字段本身未必有统一修订号：RSSD-00/02要清点公共发布/编辑/撤回的写入口，捕获白名单资料字段及授权/关联版本的指纹。提交构建前重查；读取时字段或版本不匹配的公共贡献先排除，待重建恢复。不得假设任意Source编辑都会自动递增publication.policy_version，也不能只比较构建开始时的一次快照。

公共来源发布/修改后，复用 `runtime.py` 的维护循环：比较本地公开资料版本，仅在输入改变时构建；防抖合并多次变更，单次有界，从变更到可检索目标60秒。失败保留旧快照并记录积压，撤回仍立即由读取授权兜底。目录构建不得阻塞control/sync tick；若同步执行不能满足原有heartbeat/stall预算，应复用现有受控后台执行方式并先证明单一在途构建。无变化不生成新快照，不新增进程或调度服务。

发布由单一服务负责：显式管理命令和Worker均使用预期活动checksum与输入版本CAS；完成构建后在短事务内再次核对公共资料/编辑/种子版本。旧构建不能覆盖新版本；发布失败保持旧目录且不终止采集循环，按有界退避重试。当前启动及每日无条件`import_pinned_seed()`必须一并修正：种子仅在首次无目录或受审配置明确升级时参与构建，不能把活动v2或手工回滚快照自动改回v1。回滚同步固定所选输入版本，直至下一次显式发布/解除固定，不能在下次tick被“纠正”。

撤回公开、策略封禁和权限收紧在每次返回结果时重新判断，不能等待投影刷新。**在搜索匹配、分类/语言筛选、排序、计数与分页之前**排除失效公共资料贡献；列表、详情与facets遵循相同规则。若同一URL存在独立公开目录记录，只以其自身字段重新判定命中和展示，移除被撤回Source的名称/简介/别名/provenance、状态及文章关联。不能仅分页后隐藏预览，或保留由已撤回简介带来的命中。旧快照回滚也不恢复公开授权。

### 3.3 数据变化

| 实体 | 计划变化 |
|---|---|
| `FeedDirectorySnapshot` | 保留 checksum、active、provenance；v2 增加/记录公共资料版本与编辑配置版本 |
| `FeedDirectoryEntry` | 增加规范身份 key、网站地址、别名、稳定分类 key、可查询规范化文本、精选权重/理由、多来源 provenance、可选公共 Source 引用 |
| `DirectoryVerificationEvidence`（拟新增） | 独立保存可信核验结果、时间、环境、引擎/政策版本和安全原因；不写入外部种子，不授权文章访问 |
| 既有采集与用户实体 | 不变更身份规则，不迁移用户状态，不重建订阅 |

使用增量迁移；迁移文件序号以实施时真实 migration graph 为准。Schema 和迁移由一个写入者维护。

公共与外部资料贡献必须可在数据库中独立过滤，不能只塞进一个无法安全检索的合并JSON。RSSD-00/02冻结最小子表或等效关联结构；它是目录派生数据，不能复制SourcePublication作为授权事实。核验证据同样保留来源类型与来源版本，公共授权撤回后不再公开其健康/时间信息。

### 3.4 搜索实现

V1 使用当前业务数据库与 Django 查询，不新增 Elasticsearch、Meilisearch 或向量库，不在用户浏览器下载整个目录。

导入时生成 NFKC/casefold 规范化字段；英文按词边界和已审别名匹配，中文支持连续子串；多词查询采用 AND，单词的受控同义表达采用 OR。例如 `AI / 人工智能`、`开源 / open source`，只维护有限、可审查词表，不调用模型生成无限扩展。

查询最多 200 字符、10 个词项、每项至多 5 个同义展开。参数化查询；`%`、`_` 等作为文本处理，不作为用户提供的 SQL 通配语法。

SQLite自带的大小写比较不能替代Unicode casefold；导入时物化规范字段，规范化后再校验长度。词边界匹配在规范词项表示上完成，不要求更换SQLite扩展；`AI`不能靠命中`email`通过。分类可多值归属，但精选验收每条只能计入一个主分类，避免重复凑数。

排序分层：精确名称/别名/Feed/域名 → 名称前缀 → 分类与标签 → 名称子串 → 简介。层内按命中覆盖、明确编辑权重、规范名称和稳定 ID 排序。实时健康变化只影响状态和允许操作，不在翻页中随意重排整个结果。

先在数据库过滤、排序和分页，再批量补全当前页个人状态。不能每次加载全表到 Python 排序，也不能每个结果单独查询文章和订阅。

本地数据库方案必须通过 10,000 条数据压力门禁；不达标先依据 profile 优化查询与索引，再单独评审更重方案，不能悄悄引入新服务。

### 3.5 可信状态

健康度使用 `unknown / ok / error / stale`；“更新较少”与“连接失败”分开。低频博客不能因发布时间久就判故障。

健康证据与 URL/身份、网络环境、核验时间、政策和引擎版本绑定；这些条件改变后不能继续作为当前成功证据。页面明确“上次核验成功”，不保证永远在线。

原有目录 `executable` 只能表示当前允许发起操作，不能变成成功保证；新增 `availability` 和 `health` 明确区分。

### 3.6 推荐排序

采用受审元数据中的精选列表/权重与分类配额，过滤已封禁及失去公开资料授权的条目。推荐理由来自确定规则。编辑精选与当前健康独立：核验证据超过7天只使健康转stale、移除“近期已验证”文案，不自动移出编辑集合或改变排序；连接失败单独提示，动作由当前策略决定。

V1不使用订阅人数排序，不从私人订阅推断公开热度。没有近期成功证据时仍可展示真实标为“尚未核验/核验已过期”的编辑精选；没有编辑数据时展示空态并提供普通目录浏览。发行时24个精选的近期真实证据仍是独立验收目标，不构成无人维护的永久健康承诺。更新通过显式、有界的维护核验，不新增自动外网探测任务。

### 3.7 预览、缓存与隐私

所有 GET 只读本地状态；包括列表、详情、精选和图标回退在内，不得触发外部请求或创建订阅任务。

公共纯元数据可按快照/查询条件复用内部缓存；个人状态必须在其后分用户补全。含个人状态或受权预览的 HTTP 响应继续 `Cache-Control: private, no-store`。前端查询键包含 viewer 和筛选条件；切换账号取消并隔离在途响应。

预览仅从 `authorized_sources/authorized_news` 及对应公共成员范围获取。共享物理 Feed 不表示用户的私人历史、分类、收藏、翻译和健康诊断可以公开。未登录用户不得通过错误消息、预览计数或“已有人订阅”推断私人来源存在。

## 4. HTTP 与前端合同

### 4.1 接口复用

| API | 处理 |
|---|---|
| `GET /api/rss/directory/` | 扩展 q、mode、category、language、kind、limit、cursor；继续返回 results/next_cursor/snapshot_version |
| `GET /api/rss/directory/{entry_id}/` | 新增只读资料和授权预览；无网络副作用 |
| `POST /api/rss/discovery/resolve/` | 保持现有网站发现合同 |
| `POST /api/me/rss-subscriptions/` | 保留 feed_url/candidate_token/directory_entry_id 三种选择；对目录选择可增加可选 directory_snapshot_version |
| `POST /api/me/channel-subscriptions/` | 继续处理已发布公共 Source 的订阅，不绕过原有公共成员授权 |
| `GET /api/me/rss-operations/{id}/` | 继续跟踪当前用户的任务，完成不等于已经同步出文章 |

`mode=featured` 明确请求精选；省略 mode 时保持兼容。分类/语言维度可随目录响应返回，不单独再建一个推荐服务或一套同构端点。

搜索默认每页20，最大50。游标绑定快照、规范化关键词、全部筛选和排序版本，使用确定排序尾键；更改条件重置分页。无重复/漏项的承诺以同快照、同条件且资料授权不变为前提。授权撤回优先于分页完整性；不得为了旧游标继续返回失权结果，必要时拒绝游标并要求重查。健康过期不改变排序和精选成员。

游标无效/过期保持 400，增加清晰机器码 `directory_cursor_expired` 并提示重新加载；目录确认时版本不符返回 409 `directory_changed`，禁止订阅已变成其他目标的旧选择。旧客户端未提供版本时仍按现有活跃条目校验，ID 不复用为不同目标。

幂等恢复区分新请求与重放：尚未受理的旧选择按上述规则拒绝；同一用户、同一键且同一不可变请求已被受理，先确认既有持久请求/任务，再恢复当前授权允许显示的结果，不重新解析为另一个目标或创建第二个register。选择、分组或个人分类改变则生成新键；同键不同意图仍409。无法证明是同一意图时拒绝，不猜测恢复。需覆盖“POST响应丢失 → 快照切换/旧ID下线 → 原键重试”的负例。

默认省略mode维持原有搜索；`mode=featured`由新界面显式传入；非法mode/filter返回400，不静默回退。新增能力开关在RSSD-05随兼容API先交付，默认关闭；未知能力也关闭新界面，旧添加路径仍可用。当前前端严格校验features键集合，因此新能力放在现有capabilities响应的可选顶层extensions.rss_discovery，保留旧features集合。新客户端遇到缺失/非法扩展仅关闭新发现界面，不让旧能力整体解析失败；具体合同见[开发合同C06](开发合同.md#c06-能力与前端合同)。

### 4.2 结果结构原则

继续提供旧字段 `id/name/description/kind/public_url/executable/subscribed/cached_articles`。增量增加：

```json
{
  "site_url": "https://example.org/",
  "language": "zh",
  "category_keys": ["programming"],
  "primary_category": "programming",
  "aliases": ["示例频道"],
  "editorial": {"featured": true, "reason": "编辑精选"},
  "health": {"status": "unknown", "checked_at": null, "environment_id": null},
  "availability": {"can_submit": true, "reason": null},
  "user_state": {"subscription": "not_subscribed", "operation_id": null},
  "action": {"type": "directory_subscription", "entry_id": "<UUID>", "snapshot_version": "<SHA256>"},
  "origins": []
}
```

这是字段示意，不是实际已验证的 Feed 数据。未知值用 null/unknown，不能用 0 伪装已知统计。

`action` 由服务端按真实来源类型生成，前端按判别联合调用既有服务：目录候选 → RSS 订阅；公共 Source → 公共频道订阅；网站发现候选 → candidate_token；直接 Feed → feed_url；模板 → 展示配置要求。任何 action 都不是越权能力凭证，写接口仍重查权限。

同URL外部候选与公共Source合并时，当前用户已订阅任一有效对应关系就显示已订阅；否则优先唯一合格的公共Source action，多个合格Source按稳定规则选择并明示目标。合格判断复用 `services/channel_catalog.py:current_feed_links/subscription_status`，包括当前引擎、启用link、策略与未决操作；不能仅检查publication=public。无合格公共Source但有独立外部候选时，允许用户重新确认走RSS目录路径；公共来源专属记录失效后不得静默降为个人订阅。

两条写入合同保持区别：

- RSS目录/Feed/发现候选：沿用`/me/rss-subscriptions/`及其201/202/重放200响应，`operation_id`追踪连接；新选择可带快照版本。
- 已发布公共频道：沿用`/me/channel-subscriptions/`的`{action:'subscribe', source_ids:[id]}`，返回现有订阅列表，不伪造operation_id。为新确认界面增量支持**单一source**的可选`group_ids/category_id`，在同一短事务内校验归属和公共资格并保存新关系。重复订阅不覆盖既有分类/分组，后续修改沿用现有set_groups/set_category及版本合同；未传新字段的旧客户端行为保持。公共路径没有连接任务时，直接确认关系并读取当前频道，不启动无意义轮询。

匿名用户可浏览资料，登录前不提交网站发现或写订阅；登录返回只恢复安全的搜索条件/选择ID，重新加载能力与授权。candidate_token过期须重发现，不将其、完整URL或私人分组写入公开URL/持久存储。

### 4.3 前端组件

将现有 `DiscoverDialog.tsx` 缩为容器，拟拆分 `DiscoverPanel`、`FeedSearchBar`、`FeedFilterBar`、`FeedResultCard`、`FeedDetails`、`SubscriptionAction`。状态查询与 HTTP 放在统一 RSS discovery service，避免在多个组件复制 DTO、API 路由与状态映射。

关键词使用TanStack Query分页查询，落实“加载更多”；搜索或账号切换取消旧请求。保留 `workspaceRequest`、既有 `queryRefresh.ts:refreshRssViews`、channel/news/workspace查询键并补充发现页与添加记录失效；不另建刷新工具。首次提交、任务终态及安全重试按现有模块协同，关闭弹窗不丢失已保存任务。新增文件仅在职责确有需要时拆分，不按草案文件数验收。

| A07 | 分页 | 同版本、条件及资料授权下无重复/漏项；条件变化重置；快照变化重查；撤权优先排除失权资料，健康过期不重排 |
| A08 | 去重 | 相同规范URL跨目录仅一张卡；不同栏目/语言/参数Feed不误合并 |
| A09 | 原有频道 | 默认来源、已公开来源在合格范围内可检索；既有用户数据、ID和采集策略保持 |
| A10 | 无数据 | 无文章、无核验、未知语言分别如实显示，不生成假的标题、统计或时间 |

搜索基准先由人工定义 relevant_ids 与负例、再实现搜索；不得根据算法输出事后挑选容易通过的样例。

### 6.2 订阅和权限

| 编号 | 场景 | 通过条件 |
|---|---|---|
| A11 | 单用户重复点击 | 同一意图仅一个有效关系、不产生重复物理Feed；响应丢失且目录换版后原键能安全恢复已受理任务、不重发register；同键异意图409 |
| A12 | 两用户同一Feed | 复用正常物理身份但个人分组/已读/收藏等隔离 |
| A13 | 公共与私人 | 已发布公共Source走既有公共授权；目录同URL不能泄漏其他用户私人文章/正文/状态 |
| A14 | 退出或换号 | 旧请求、详情和缓存不显示上一账号数据；订阅请求重新校验viewer |
| A15 | 取消/失败/未知 | 刷新或关闭后任务仍可追踪；取消自己的意图不删除其他用户共享Feed |
| A16 | 公开撤回 | 下次请求的列表、详情、搜索命中、筛选、facets、健康和预览均不含撤回贡献；保留同URL独立公开资料须重新判定，不等待重建 |
| A17 | 版本漂移 | 目录变更、网关/引擎/权限版本变化不会把旧选择发送给新目标或提交旧结果 |
| A18 | 身份与CSRF | 未登录写请求拒绝，CSRF/只读站点规则不退化，越权资源不泄漏存在性；越权分组使公共订阅整笔回滚；新关系分类/分组原子保存，重复请求不改旧设置 |

### 6.3 安全与负例

| 编号 | 场景 | 通过条件 |
|---|---|---|
| A19 | 恶意网络输入 | 拒绝内网、loopback、链路本地、云元数据、凭据型URL；重定向与DNS变化逐跳检查，实际拨号保留现有防护 |
| A20 | 元数据攻击 | HTML/脚本不执行；XML外部实体、实体膨胀、超深层级和超量输入被现有安全解析限制拒绝 |
| A21 | 只读零副作用 | 列表/详情/精选GET外部请求数=0，采集任务和订阅数变化=0 |
| A22 | 目录更新失败 | 错误格式/checksum/空目录/超限/事务失败后旧快照可用；失败不终止sync；启动/每日/迟到构建不覆盖活动v2或固定回滚版本 |
| A23 | 核验隔离 | 未订阅候选核验只在隔离环境；不复制生产DB/密钥，不污染实际订阅 |

### 6.4 性能目标

这是待实测的发布门禁，不是已经取得的跑分：

RSSD-00先记录现有接口的同条件基线与测量脚本口径，再冻结目标；不得为达到SQL数字删掉授权。10k是既有上限的容量验证，实际首批200+数据也要测。首批验证与10k压力分别报告，不因压力夹具多而扩充真实频道范围。

- 测试资源约束：2 vCPU、4 GiB；记录CPU型号、数据库/运行时版本、构建模式与数据checksum。
- 10,000 条元数据、每页20条、10并发；预热后至少1,000个混合查询样本。
- 本地API耗时 p95 ≤ 300ms，p99 ≤ 800ms；计时覆盖鉴权后的查询、ACL补全与序列化，不混入公网传输时间。
- 每页业务SQL ≤ 12；从20条提高到50条，SQL数量增长 ≤ 2；鉴权/会话查询另列，不以排除核心工作美化数据。
- 20条列表响应未经压缩 ≤ 80 KiB；不包含正文、base64图标或目录全集。
- 500次目录浏览/搜索后，Miniflux Feed数、Source数和用户订阅数不因这些GET增加。

SQL数量只作为防N+1门禁，不能为了数字绕过 ACL。性能未达标就记录FAIL并优化，不把目标改成实际值。

### 6.5 真实环境与浏览器

真实隔离引擎至少覆盖：原生Feed、网站返回多个候选、未发现Feed、失效/非法Feed、URL重定向、重复订阅及首次文章同步。RSSHub仅对当前实际启用能力做回归；未启用明确NOT_RUN，不阻塞原生Feed首版，也不能标记通过。

浏览器覆盖未登录、普通用户、管理员；桌面与412px；键盘、Escape、关闭后焦点、中文IME、快速改词、登录后返回、刷新/后退、换号、超时和重试。提交连接成功和已经能读到文章分别记证据。

证据至少记录：base/head SHA、目录checksum、命令、退出码、测试范围、实际请求与响应、截图/trace、实测性能、PASS/FAIL/NOT_RUN/BLOCKED。Mock通过、隔离真引擎通过、生产通过三种状态不能相互替代。

## 7. 发布、维护与回滚

### 7.1 发布顺序

在隔离/经授权的本地环境中部署兼容v1/v2的后端、增量迁移及runtime发布修订 → 能力开关默认关闭 → 导入/验证新快照 → 完成本地/隔离验收 → 开启 `RSS_DISCOVERY_V2_ENABLED` 小范围体验。生产部署另行授权；目录发布不执行正文采集或用户批量订阅。

前后端以服务端暴露的能力开关协同，不能让前端先请求后端不存在的合同。不得为了新目录调用 `rss_initialize --reset` 或任何 `reset_content` 路径。

### 7.2 维护

首版来源更新通过有审查的目录变更流程；不新建无人审核的热更新服务。记录目录版本年龄、导入拒绝原因、精选证据过期数、查询耗时和错误类型。指标不采集完整凭据URL、其他用户私人订阅或未经同意的原始查询历史。

公共资料投影复用现有Worker的本地维护，不新增常驻进程；监测构建积压/失败及heartbeat，不能为目录刷新拖慢采集。公开撤回仍由读取时授权兜底。精选核验过期只降级状态；维护人按需显式复核并保存环境证据，不授权自动外网扫描。

### 7.3 回滚

关闭新界面/能力开关 → 原子切回上一个活动目录快照并固定相应输入版本 → 保留新迁移和证据记录 → 沿用原有RSS添加和频道管理。演练至少跨过一次维护tick及模拟启动/每日检查；活动版本不被自动覆盖。目录回退不得删除已经建立的订阅、FeedBinding、文章、分组或用户状态。

若有公开资料泄漏，先撤销相应公共访问与禁用新展示，再调查；不以删除用户内容作为回滚方式。

## 8. 风险与设计决定

| 风险 | 决定 |
|---|---|
| 上游目录数量很多但Feed失效 | 把目录候选和核验成功分开，精选有独立证据 |
| 第三方桥接服务不稳定 | 标明依赖，优先原生；不静默替换网关 |
| 搜索结果误合并 | 只按受支持的URL身份去重，不按标题/域名 |
| 公共投影滞后 | 新增允许短延迟，撤回必须读取时立即生效 |
| 目录更新导致ID和选择漂移 | 保留稳定ID、绑定版本、失效重选，不自动换目标 |
| 私人共享Feed泄漏 | 元数据、健康、文章和用户关系分别检查来源与权限 |
| 为了“成熟”引入重型设施 | 先复用Django、现有DB、TanStack Query与Miniflux；基于性能证据扩展 |
| 功能只交付一半 | V1必须包含UI+订阅闭环；接口完成不算验收完成 |

后续可独立评审更大目录、更多已核验RSSHub模板、模糊搜索、站内公开热度与合法授权的外部发现服务，均不纳入V1依赖。
