# RSSD-07.1：微信 RSS 正文统一处理

状态：本地功能已接入；用户验收未测。属于用户在 RSSD-07 验收期间追加的正文修复。

目标：微信转RSS渠道保留Feed自带正文，防止Miniflux二次抓微信页面用控件文字覆盖正文。

统一规则：`is_wechat_feed_url`识别`wechat2rss.*`与`wechat2rss.com`来源，不再按公众号Feed逐条加白名单；此识别仅收紧采集模式，不授予网络、正文或公开权限。已走RSSHub的来源继续沿用其既有feed模式。微信桥接来源默认feed模式且禁止切回full_content；来源、摘要、owner、CAS等已有约束仍执行。`mp.weixin.qq.com`文章的直接refetch在策略及物理调用边界均被拒绝，不调用fetch-content。

内容：现有Markdown转换、图片处理、清洗和正文CAS保持不变。微信控件-only以及已知的纯异常/删除/访问频繁响应不作为正文接受；真实短文及带控件页尾的正常文章不受影响。未确认完整性不标成已确认全文。无法保证上游始终提供内容，未对任意第三方桥接产品作兼容保证。

涉及文件：`backend/api/rss/feed_policy.py`、`engine.py`、`content_store.py`；显示沿用此前已修正的FullContentSection。无新模型、迁移、接口或采集器。

既有内容恢复：通过change_policy统一设置当前微信来源为feed模式，再提交refresh_feed，Miniflux读取RSS，现有sync/CAS回填正文。新智元RSS命中304缓存时临时设置该Feed的ignore_http_cache，只提交一次新的持久刷新任务；确认恢复后已将缓存设置还原。未直接把诊断HTTP内容写入新闻。

验收：

1. 打开本地 `/news/158`，应看到新智元图灵奖文章的正文和图片。
2. 打开 `/news/126`，确认机器之心正文仍正常。
3. 添加本目录另一条微信转RSS来源，后端应使用feed模式；不能改为二次抓取微信页面。
4. 上游内容缺失或异常时如实显示状态，不把控件/错误页当正文；用户关系、收藏和文章ID不变。

定向验证已通过：两个现有桥接服务与另一个同类型域名默认feed、普通站点策略不变、摘要限制保持、微信原文物理refetch被拦截、异常响应拒绝、短文保留。使用进程内存数据库，无模型/业务网络调用。完整自动回归和新增来源的真实订阅验收未执行。

本地核查：新智元20条已更新为RSS正文，目标158为10416个Markdown字符；机器之心10条无控件-only正文；两个绑定均feed/ready。未逐篇与微信原文逐字比对，完整性仍unknown。

回退：撤回三个源码文件的本轮统一规则、恢复本地额外代码挂载并重启对应本地进程；保留已恢复的文章与订阅。不要把模式直接改回full_content导致再次覆盖。目标旧模式和版本见交付记录；变更仍走change_policy，不直接改策略版本。
