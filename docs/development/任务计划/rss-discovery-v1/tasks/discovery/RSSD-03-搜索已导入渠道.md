# RSSD-03：搜索已导入渠道

> 状态：功能已接入本地环境；用户验收：未测。见[本轮交付](../../MVP-开发交付与验收.md)。

**做什么：** 用户在现有添加订阅入口输入渠道名称或RSS地址，就能找到已导入的渠道。

**前置：** RSSD-01的目录已接入。

**怎么做：** 复用GET /api/rss/directory/?q=...及已有search_directory，不重写搜索算法。完善现有DiscoverDialog的输入即搜索、结果显示、空结果和“加载更多”，不区分中英文，不加语言筛选/同义词/排名指标，不新建发现页。

**涉及文件：** frontend/src/features/rss/DiscoverDialog.tsx；只在确有缺口时最小修改backend/api/rss/directory_http.py或directory.py。复用workspaceRequest和现有viewer隔离。

**输入输出：** 输入普通关键词/名称/地址，输出已有目录中匹配的渠道；未搜到如实显示空结果，不自动访问外网或新增来源。

**开发步骤：**

- [x] 接通已有q查询与结果展示，空输入可浏览目录。
- [x] 用既有cursor提供加载更多，更换关键词重置旧结果。
- [x] 给用户入口和示例名称，请用户实际搜索验收。

**你怎么验收：**

1. 输入一个OPML中明确存在的渠道名称，无需点按钮，停顿约250毫秒后能找到对应渠道。
2. 输入名称的一部分或RSS地址，仍能找到相应结果。
3. 输入不存在的内容，显示“没有找到”，清空后自动恢复目录；中文选字期间不查询，选字完成后显示结果。
4. 加载更多不会重复卡片；换关键词后没有残留上一轮结果。

**完成标准：** 用户能从已导入清单中搜索定位频道并选中；不设搜索语言、评分或容量指标。

**测试安排：** 自动化测试后补；只做必要的构建/启动检查，让用户实际测试交互。

**回退：** 回到原添加弹窗与既有查询，不改用户订阅/文章。
