# RSSD-07：订阅搜索结果

> 状态：功能已接入本地环境；用户验收：未测。见[本轮交付](../../MVP-开发交付与验收.md)。

**做什么：** 用户搜索找到渠道后，可以选中并订阅，在我的频道或添加记录看到结果。

**前置：** RSSD-01和RSSD-03可用。

**怎么做：** 沿用现有directory_entry_id选择、POST /api/me/rss-subscriptions/、个人分类/分组确认和operation查询，由Miniflux继续连接。只修接线/提示/刷新缺口，不新建订阅接口、任务队列、公共频道发布或健康系统。

**涉及文件：** frontend/src/features/rss/DiscoverDialog.tsx、queryRefresh.ts；必要时最小修改backend/api/rss/subscriptions.py或subscription_views.py。现有CSRF、owner、幂等、地址限制保留。

**输入输出：** 输入选中的已有目录条目及自己的分类/分组，输出持久订阅请求和当前连接结果；只订阅用户确认的这一项。

**开发步骤：**

- [x] 将选中目录条目接入现有确认和订阅请求。
- [x] 显示已保存/连接中/失败原因，并刷新我的频道与添加记录。
- [x] 给用户从搜索到订阅的完整入口，请用户实测；连接与首次文章同步分别提示。

**你怎么验收：**

1. 搜索一个受支持渠道，选中并确认订阅。
2. 在我的频道或添加记录找到该渠道，看到真实连接状态。
3. 再次操作同一渠道，该渠道应从添加列表和搜索结果隐藏，不出现重复订阅；我的频道中仍保留该渠道及自己的分类/分组。
4. 等待后台首次同步后能打开文章；若失败，能看到原因，不显示假成功。

**完成标准：** 用户能完成“找到已有渠道→确认订阅→看到关系/连接结果”；文章同步是否完成单独记录。

**测试安排：** 先提供可运行功能和人工验收步骤，自动化测试后补，不安排大规模验证工程。

**回退：** 恢复旧添加界面，保留已建立关系、任务记录及文章；不清数据库。
