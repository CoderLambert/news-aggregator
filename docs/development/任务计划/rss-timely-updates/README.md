# RSS 新文章及时更新

用户目标：订阅来源更新后尽快收录，并在页面提示新增内容，保留当前阅读位置。

- Miniflux：默认调度周期及 round-robin 最小间隔由 60 分钟缩短为 10 分钟；分别通过 `RSS_POLLING_FREQUENCY`、`RSS_POLLING_MIN_INTERVAL` 覆盖。原站缓存、限流、队列仍可能延迟，10 分钟不是到达保证。已有 feed 的 next_check_at 不回写，下一次正常检查后采用新周期。
- NewsHub：保留现有约 30 秒增量同步，不新增采集引擎。
- 页面：每 30 秒检查当前账号与筛选下的第一页；隐藏标签页暂停，窗口重新获得焦点或页面重新可见时检查。后台检查与正在阅读的列表使用独立查询，不替换列表、不自动滚动。
- 发现新增内容时显示“有新文章，点击更新”，点击后加载第一页。使用通用提示而非精确篇数，因为首页有分页上限，删除/屏蔽等也会影响总数。
- 搜索状态不后台轮询，避免反复执行搜索。复用现有 DTO、AbortSignal、订阅访问控制与 viewer 查询键，旧账号结果不能污染新账号。

验证：Node 22 定向列表/账号/搜索回归 23 项通过；typecheck、lint（已有一项无关 warning）、build 通过。两个 Compose 合约函数在 Python 3.12 临时目录中直接执行通过，未运行完整 pytest、全量 CI 或真实发布到收录的时延测试。

本地交付需保留现有 UI 补丁并单独构建；不覆盖其他功能的源码。静态资源先复制、index 最后原子替换，保留旧资源及完整备份。仅重建指定本地 Miniflux 服务，不改数据库身份、凭据、订阅与历史内容。

手工验收：刷新站点后保持列表打开，新内容入库后约 30 秒内出现提示；提示出现时原列表不变，点击后加载最新列表；切换订阅/分组/账号后只显示对应范围。实际文章来源更新时间和缓存不由 NewsHub 保证。

回退：恢复原静态 index 与备份资源；移除本地 Miniflux polling override 并仅重建该服务。仓库变更可独立 revert，无数据库迁移。
