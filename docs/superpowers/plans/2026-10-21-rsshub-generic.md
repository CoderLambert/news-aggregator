# 通用 RSSHub 接入修正

用户明确纠正范围：支持通用 `rsshub://namespace/path?query`，不逐条新增路由白名单。沿用现有RSSHub、Miniflux、身份绑定、审计、个人订阅及发布审核。Twitter继续跳过。原worktree脏改动保留，不提交/推送/部署生产。

1. 通用规范化仅检查结构、路径穿越、控制字符、凭据和服务端保留选项；支持无参数路径、Unicode、编码路径参数、查询参数和真实内容ID。未知路由交给RSSHub返回，不先报格式错。
2. 固定站点HTTPS网关转发通用路径，禁止用户改变上游host/认证/header；服务端点和Twitter保持关闭。泛化接入不授予RSSHub服务凭据。
3. RSSHub进入无公网默认路由的独立内部网络，仅通过成熟Squid代理访问公网HTTP(S)。外部IP/DNS/跳转均经过代理私有地址拒绝；拒绝直连绕过。现有Miniflux专用代理仍只允许精确网关主机。
4. 此机器所有普通UDP DNS（包括指定1.1.1.1）被Fake-IP接管；公网出口代理通过固定DoH解析器获得实际地址，198.18仍拒绝，不增加Fake-IP例外。不改宿主代理或DNS。采用固定镜像AdGuard dnsproxy，TLS验证开启、无宿主端口。
5. 原已验收的Feed13保持原URL/版本/账号；其既有准入哈希不改变。新通用绑定另有generic_version和停用名单版本边界。既有正文和七天下界不重置。新通用内容采用Feed-only与摘要策略。
6. TDD：多种路径/查询/编码、凭据/穿越、OPML、版本失效、已确认源站错误。实际隔离引擎验证freecomputerbooks、其他namespace、未知路径、代理内网/元数据/域名解析/跳转及直连拒绝。
7. 定向回归、一位新上下文复核、本地备份与同镜像app/Worker升级、浏览器实际完成订阅和首页显示。失败来源按真实状态记录，不以全绿为目标。

Ruling：本轮为已授权功能范围纠正，直接实施，不重复要求用户批准已表达的通用目标。新增出口组件仅为统一网络边界，不形成新采集器；RSSHub保持生产Feed、Miniflux保持采集。
