# RSS 自助订阅、公共频道新增与审核员权限设计

日期：2026-10-21。状态：方案方向已获用户确认；本设计文档待用户审阅，尚未开始本轮产品实现。

## 1. 用户目标与范围

用户需要自己添加 RSS 后即可使用，不依赖管理员逐条登记；希望授权普通账号成为频道审核员，分担公共频道审核；同时补齐上一轮频道核验页缺少的“新增公共频道”入口。

已确认采用：**个人订阅自动连接，公开推荐人工审核，审核员单独授权**。个人可见性不因连接成功而改变；公开频道需要人工授权与技术核验同时满足。超级管理员直接新增公共频道时，登记行为本身构成人工授权，技术核验成功后自动开放订阅。

本轮交付本地版本。保留上一轮核验恢复实现、已有账号、订阅、文章和审计；不部署生产，不推送或合并代码，不接入付费服务。

## 2. 当前代码事实和实现基线

工作目录为 `news-aggregator-channel-recovery-20261021`；分支为 `task/channel-recovery-20261021`，编写前 HEAD/base 为 `b03a3dfb41911b06dfb24c31074f4faf60fe8845`。上一轮频道恢复与列表改动仍未提交，不能仅用 HEAD 描述运行中的候选版本，沿用其[独立验收记录](../../verification/channel-recovery-2026-10-21.md)。原始工作目录的数据库及未跟踪文档继续保留。

已核对以下现状，均为源码证据，不等于本轮运行验收：

- `DiscoverDialog` 已支持目录、网站发现和直接 RSS 添加；`subscribe()` 通过 Miniflux Worker 建立个人订阅，不要求管理员批准。
- 连接成功前，持久请求位于 `FeedOperation.safe_input.subscription_request`，尚无 `ChannelSubscription`；现有仅查询订阅关系的接口不能完整展示这些待处理请求。
- `SourcePublication` 已区分 `personal/public`；`FeedBinding` 是实例、账号和 Feed 的物理连接，不能充当用户所有权。
- 频道核验 API、前端路由、Worker 派发与提交均有超级管理员检查，授权审核员必须覆盖所有这些位置。
- `access.py` 多处按 `SourceFeedLink` 与共享 binding 派生文章可见性。新增公共链接可能立即放开历史文章；仅新增一个 public Source 不能证明私人历史安全。
- `SourceConfig` 是既有版本化来源采集合同。普通 RSS 的公开推荐不自动创建该合同，也不能利用推荐绕过其中的禁用、摘要限制或版本审批。

复用 Session/CSRF、`RssAPIView`、URL/来源策略、`EngineAdapter`、操作队列、ControlWorker、同步和存储阅读器；不另建 RSS 解析器、认证体系或任务系统。

## 3. 用户流程

### 3.1 添加和使用个人 RSS

保留“添加订阅”的单一入口：输入网站或 RSS、选择发现结果及个人分组、确认添加。显著说明“仅加入我的订阅；公开推荐需要另行提交”。

已连接且策略一致的 Feed 直接复用；新 Feed 持久化连接任务后异步连接。成功后自动加入“我的订阅”，文章同步独立显示为“等待首次同步/已有文章/暂无文章”，不把连接成功描述成文章已经到达。

“我的订阅”增加可刷新、可重新打开的“添加记录”，涵盖等待连接、连接中、已连接、失败、结果待核对和已取消。失败原因使用安全中文说明；明确失败允许显式重试，结果未知只允许安全对账，不盲目再次创建。用户可取消自己的未完成添加，取消后迟到结果不能恢复订阅。

个人操作只允许改变自己的订阅意图。它不能暂停共享 Feed、改变全局采集模式或其他用户的任务。共用连接失败时，重试仍遵守共享操作合并、幂等、冷却和恢复边界。

用户关闭弹窗、刷新页面或换设备后，通过自己的添加记录继续查看。账号切换后清理查询和选择；旧响应不能写入新账号界面。

### 3.2 推荐公共频道

已成功连接且属于自己的订阅提供“推荐到公共频道”。提交时明确展示：公共 RSS 地址、拟公开名称、分类、语言、推荐说明以及公开范围。用户确认后才将这些资料交给审核员。

公共推荐只接收公开、无凭据的 HTTPS Feed。token、Cookie、用户名密码或其他授权型 RSS 本轮继续拒绝；“个人订阅”表示订阅关系私有，不表示已经支持需要凭据的 RSS。

提交后用户可查看审核进度、驳回原因，并在决定前撤回。驳回不影响个人订阅。修改 URL、公开范围或其他影响授权的字段会产生新版本，旧审核结果失效；更正后可以重新提交。相同实例和账号内的相同 Feed 推荐合并到同一候选，分别保留提交者及撤回记录，不公开其他提交者身份。

### 3.3 审核与发布

审核页复用“频道核验”页面布局，区分“公开推荐”和“连接核验”两个队列。前者默认显示待审核，后者保留上一轮待处理列表。筛选、搜索、分页、详情和返回位置保存在 URL。

审核员查看用户主动提交的资料、Feed 来源和已授权的预览内容，可以调整公开名称和分类、通过或填写原因驳回。连接失败或未知时可执行具有当前权限的核验恢复；技术成功不自动替代人工通过。

发布条件为：当前推荐版本已获有效人工通过、当前实例与账号匹配、来源策略允许、连接已核验且无未解决未知操作。任一条件变化，发布事务拒绝旧结果。人工通过但技术未完成时显示“已通过审核，等待连接”，暂不进入公共目录或开放公共订阅。

已经发布的频道不因审核员日后被撤权自动下架；尚未发布且批准权限已经撤销的推荐，必须由其他有权人员重新确认。审核和撤权操作通过同一授权记录的 SQLite 写入预留串行化，确定先后顺序。

### 3.4 超级管理员直接新增

“频道核验”页增加“新增公共频道”：名称、RSS 地址、分类和语言，提交按钮为“新增并核验”。登记时记录超级管理员人工授权，随后进入同一连接核验服务；成功后自动发布，失败或未知保留真实状态及下一步动作。

重复提交返回既有任务；相同 Feed 已公开时跳转现有频道，已在候选队列时展示该候选。不得重复创建物理连接。

审核员新增公共候选时走推荐流程，不能通过“新增”绕过不得自审的限制。

## 4. 权限与授权生命周期

| 操作 | 普通用户 | 频道审核员 | 超级管理员 |
|---|---|---|---|
| 添加个人 RSS、查看和取消自己的添加 | 可以 | 可以 | 可以 |
| 提交/撤回自己的公共推荐 | 可以 | 可以 | 可以 |
| 查看推荐队列和公共频道技术状态 | 不可以 | 可以 | 可以 |
| 核验恢复公共频道、通过或驳回推荐 | 不可以 | 可以，自己的推荐除外 | 可以 |
| 直接新增并授权公共频道 | 不可以 | 不可以 | 可以 |
| 授予/撤销审核员 | 不可以 | 不可以 | 可以 |
| 引擎管理、全站采集策略、搜索索引维护 | 不可以 | 不可以 | 保持现有权限 |
| 查看其他人的私人订阅、阅读和 AI 历史 | 不可以 | 不可以 | 本功能不提供此入口 |

复用 Django 用户和权限体系，新增一个业务能力 `review_public_rss`；不得通过设置 `is_staff/is_superuser` 授权审核员。新增持久授权记录保存授予者、有效状态及递增版本，并记录撤销和重新授权事件。业务授权函数是页面、API、Worker 的统一入口；角色名称不构成另一套身份系统。

登录与 `/auth/me/` 返回明确的 RSS 业务能力。缺少或未知能力按无权限处理；审核员只能进入审核页面，不获得运行概览、引擎和索引管理权限。公开推荐的审阅接口只返回允许公开的资料，不复用返回私人订阅或操作完整 safe_input 的接口。

授予和撤销由超级管理员在站内“频道审核员”页面完成，使用精确用户名查找，不列出邮箱和其他个人信息；授予前显示账号确认，不能自助升级权限。

审核请求捕获授权版本、推荐版本和 binding/policy/publication 版本。Worker 在领取、发出网络请求前及提交结果时读取当前活动账号和授权版本；撤权、禁用账号或重新授权都会使旧授权任务失效。已经发出的远端请求仍可能执行，但其迟到结果不能发布频道；远端结果进入原有安全对账。

## 5. 持久化与状态

采用以下业务记录；具体字段命名可遵循仓库约定，语义不得省略：

- 审核员授权：用户、实例、有效状态、版本、授予者和时间；授权变更事件只追加保存。
- 公共候选：实例/账号/binding、拟公开元信息、公开范围、递增版本、创建方式、当前审核状态、当前有效决定、最终公共 source。一个 binding 同时只有一个有效公共候选。
- 推荐提交：候选、提交用户、该用户提交的说明、提交/撤回时间。审核员只见主动提交的资料，其他普通用户看不到这些提交记录。
- 审核事件：候选与版本、动作、操作者与授权版本、原因、时间、幂等键和请求摘要。不得覆盖原决定或以清空错误伪造成功。
- 公共文章成员记录：公共 source、EngineEntryMap、发布授权版本及已验证内容范围。该记录是新公共频道的文章访问依据，防止一个公共链接使整个私人 binding 的历史自动公开。

候选审核状态为 `pending/approved/rejected/withdrawn/published`；连接状态继续复用现有核验状态。最终能否发布从当前审核版本、权限和连接证据判断，不把两个维度压成一个绿色状态。

个人添加记录优先从已有 actor-scoped FeedOperation 构造，不新增重复操作队列。显式重试关联前次操作，保留原错误、次数、执行阶段及取消记录；未知请求复用上一轮恢复证据规则。

## 6. 公开与个人数据的边界

公开发布创建独立的公共 Source/SourcePublication，保留原个人 source、订阅、分组和用户历史；相同 URL 的物理 FeedBinding 继续复用。

公共范围限定为公开 Feed 提供的文章数据。首轮范围为发布时最近七天内的可验证文章，同时不得早于 binding 原有 `published_since`；后续正常同步的新文章按策略加入公共成员。时间无法可靠确认的旧文章不补入公开范围。审核确认页必须明确这项范围。

发布不得通过增加公共 `SourceFeedLink` 直接取得整个 binding 的文章权限。新增公共频道的 ACL、文章计数、搜索、详情、翻译、研究、TTS、向量检索与导出必须使用公共文章成员记录；已有个人关系仍按原授权访问。只在公共成员中出现的文章才可通过新公共频道被看见。

公共成员的生成必须具有当前授权版本、引擎身份和 Feed 对应证据。初次发布可从 Miniflux 已存条目进行有界同步，复用已有 sanitization 和版本围栏；不重新初始化引擎，不重置全局 cursor，不对发布者额外抓取正文，不为满足公开范围放宽七天采集下界。

已有 News 可按 URL 和内容来源复用，但不能把私人翻译、研究、收藏、分组、原始响应或凭据加入公共投影。私人上下文的正文不能仅凭添加公共链接获得公共读取授权；须满足同一公开 Feed 的独立来源证据及当前正文策略，否则公共端先显示安全摘要。保留原正文和所有者记录，不通过改写 provenance 伪造公共来源。

已有公共频道继续按原合同提供历史，不把本轮新的发布范围追溯应用为删除历史。新增公共频道显式标记使用成员授权，旧记录保持兼容。

## 7. HTTP 与前端合同

所有端点同域 `/api/`，继续 Session、CSRF、read_only 禁写及 `private, no-store`。GET 只读本地状态，不触发采集或审核。

| 入口 | 合同 |
|---|---|
| 现有 `POST /me/rss-subscriptions/` | 保持请求和幂等合同，默认个人订阅 |
| `GET /me/rss-additions/` | 当前用户的持久添加记录，支持状态、页码，返回可执行动作 |
| `POST /me/rss-additions/{id}/actions/` | 显式重试、对账或取消，包含预期版本与幂等键 |
| `GET/POST /me/rss-recommendations/` | 当前用户推荐记录；从其现有个人订阅提交 |
| `POST /me/rss-recommendations/{id}/actions/` | 更新后重提或撤回，校验预期版本 |
| `GET /admin/rss/recommendations/` | 有权限人员的推荐队列及筛选数量 |
| `GET /admin/rss/recommendations/{id}/` | 推荐资料、技术证据、安全预览和审计 |
| `POST /admin/rss/recommendations/{id}/decisions/` | 通过/驳回，包含预期版本、幂等键，驳回须原因 |
| `POST /admin/rss/sources/` | 超级管理员新增并授权；已有 GET 保持分页合同 |
| 现有核验与批量核验入口 | 复用恢复服务，增加能力和授权版本检查，不扩大私人范围 |
| `GET/POST /admin/rss/reviewers/` | 超级管理员查看有效授权、按精确用户名查找并授予 |
| `POST /admin/rss/reviewers/{id}/revoke/` | 超级管理员按预期授权版本撤销 |

重复幂等键和相同请求复用结果；键被用于不同内容返回 409。权限不足返回 403，不属于当前用户或实例的私人目标返回 404；过期版本返回 409；限流返回 429 和 Retry-After。所有动作返回下一步和机器可读原因，不暴露原始远端错误体。

前端复用 TanStack Query、workspaceRequest、现有 modal/drawer；查询键包含 viewer，审核任务还区分授权版本。添加记录可独立导航；未完成任务不能因弹窗卸载而消失。公共推荐和审核任务的查询分页每页 25，可选 50；连接批次仍最多 50。

审核员页面使用独立业务能力门禁，不能被现有全局 `admin` 超级管理员 UI 门禁误拦；全站管理页面继续原门禁。桌面详情为抽屉，412px 为全屏；支持键盘、Escape 和关闭后的焦点恢复。

## 8. 资源与错误处理

保留现有个人订阅上限和每小时网站发现限制。新增个人连接请求按账号限流，默认每小时 20 个不同新增目标、同时最多 5 个未终结目标；相同目标幂等重放不重复计费。未知任务占未终结名额，用户可取消自己的意图，但取消不清除共享未知结果。

公共推荐每人同时最多 10 条有效未决定提交，每小时最多 20 次新提交；撤回后重提仍计入小时限制。同一候选的重复点击不增加记录。以上新增限额由服务端设置配置，在任务事务内原子检查；超额显示可理解的等待时间或处理已有任务的建议。

共享 binding 并发连接合并；普通用户取消只移除自己的有效引用。暂停、来源禁用、策略收紧、实例切换、撤权和版本变化均阻止过期提交。网络 I/O 在事务外；SQLite 写入使用现有预留/CAS 和有界重试。429 沿用 Retry-After，新的超时保留未知并进入对账。

## 9. 验证与交付条件

两项关键安全假设目前均为 **UNPROVEN**，必须在实现后提供运行证据：

1. 共享物理 Feed 不扩大私人数据可见性。最便宜负例：两个用户共享 binding；发布公共候选后，未获公共成员授权的旧文章、私人正文来源、翻译和个人记录仍无法从匿名/第三方列表、计数、搜索、详情及 AI/TTS 入口获得。
2. 撤权和版本变化能阻止后台旧结果。最便宜负例：暂停在发送前和响应后两个位置，撤销或重新授予审核员、修改推荐、取消请求；旧租约/授权版本均不能发布，远端未知结果不能触发第二次创建。

离线测试覆盖：普通用户添加与持久进度、成功/明确失败/未知/取消、重复点击和并发；跨用户/跨实例隔离；来源政策；CSRF 与只读站点；自审拒绝；授权增删和撤权竞态；推荐去重及撤回；人审通过与技术成功的两种先后顺序；公共范围和所有存储阅读消费者；旧公共频道兼容。

真实验证使用隔离 Miniflux 与合成账号/DB，覆盖个人添加立即使用、公开发布复用已有 Feed、明确失败、未知恢复和已有正文保留。浏览器覆盖普通用户、审核员和超级管理员三个角色；刷新/返回、账号切换、失败恢复、倒计时、空结果、键盘及 412px。不得用组件测试冒充真实角色验收。

按受影响范围执行 Python 3.12 后端测试、Node 22 前端测试/typecheck/lint/build；不复用上一轮测试数量证明新权限和发布安全。记录精确候选、实际命令与 PASS/FAIL/NOT_RUN，CI 和生产未运行分别标明。

## 10. 实施边界与回退

本设计是一条完整业务链，按单写者顺序实现：持久化与权限 → 个人添加记录和动作 → 公共候选与成员授权 → 管理员新增和审核页面 → 三角色集成验收。共享 schema、迁移和路由由同一实现者维护。

新增迁移接续实际 graph，不改已应用的 0075/0076。先安装迁移和支持新围栏的 Worker，再开放新入口；授权数据缺失时默认只有原超级管理员能力，不能把历史 staff 账号自动升级为审核员。

回退通过关闭新推荐/新增/审核入口、撤销审核员能力并停止未完成新发布执行，保留审计及所有新增记录。若发现公共授权错误，先撤销对应新公共成员访问并下架该新公共 source；保留个人 source 和文章字节。不得通过清空数据库、降低迁移版本或覆盖旧镜像后继续处理新任务回退。

暂不包含：凭据型 RSS、用户控制共享抓取策略、自动按活跃度授予审核员、复杂多级审批、批量人工通过公共推荐、邮件/外部消息通知、生产发布。
