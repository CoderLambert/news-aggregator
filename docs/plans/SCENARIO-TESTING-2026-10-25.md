# NewsHub Scenario Testing — implementation specification and plan

Base: `e74f7b1a4d0964680f90a4b808f59a7b180dce9e`.
Branch: `feat/scenario-testing-msw-20261025`.
Status: implementation draft; dependency installation and Luna xhigh acceptance pending.

## Goal and scope

Run the existing NewsHub UI against deterministic synthetic API scenarios, without Django,
Miniflux, databases, real sessions or model-provider calls. Add a shared stateful mock backend,
MSW browser/Node adapters, an optional loopback-only HTTP adapter, contract tests and a
Playwright matrix. Preserve the existing API clients, parsers, query cache and production entry.

The first integrated vertical slice is news list/detail/personal read state, with the actual
startup dependencies (identity/capabilities/channels/preferences/dashboard/statistics).
RSS engine writes, AI tasks/SSE, OPML and admin workflows are NOT implemented by this slice.
Unsupported operations fail explicitly; they must not return fake success or reach a real API.

## Approach

Selected: a separate opt-in Vite configuration substitutes the HTML entry only in `mock` mode.
The production `src/main.jsx`, `App.tsx`, existing Vite config and query policy remain unchanged.
One pure Request/Response router feeds MSW and the standalone HTTP adapter. No parallel business
API client, auth provider, data store or application UI is introduced.

Rejected: copying the separate teaching app (does not test real NewsHub); replacing every service
with vi.mock (bypasses transport/parsers); forwarding unknown API requests (unsafe/undeterministic).

## Decisions / constraints

- Preserve the existing automatic query retry (one retry); the manual-retry scenario fails twice.
- ReadStateButton is confirm-on-save, not optimistic; test the actual behavior.
- Match Python RSS 401/409 error envelopes, absent read state version 0, creation version 1,
  unchanged-state idempotence, and stale compare-and-swap behavior.
- Mock auth is deliberately synthetic and not Django Session/CSRF proof. Do not overwrite cookies.
- Browser instances own independent state. Reset invalidates pending work; bounded audit logs
  contain only method/path/outcome/status, never bodies, headers, tokens or query strings.
- Unknown scenario/API fails closed. No upstream URL setting, remote bind, arbitrary proxy or live key.
- No root CI modifications or dispatches before local acceptance; preserve existing workflow routing.
- New dependency lock entries must be generated by npm in the real checkout, not hand-fabricated.
- Current environment cannot resolve npm; specified Luna xhigh acceptance agent is unavailable.
  Formal test/commit gates must remain BLOCKED; no substitute acceptance or passing claims.

## Implementation tasks and evidence

1. Write core and HTTP adapter tests before implementation; pin expected contracts independently.
   Interfaces: createScenarioBackend(id, {origin}), handle(Request), reset(), inspect().
2. Implement scenario catalog, typed synthetic fixtures and per-instance Request/Response backend.
3. Add MSW adapters and guarded mock-only Vite entry; keep production bootstrap untouched.
4. Add loopback HTTP CLI with origin/Host/body bounds, abort propagation and no proxy fallback.
5. Add actual API/parser integration tests and ReadStateButton interaction tests, without vi.mock(api).
6. Add a standalone Playwright matrix that drives existing app routes, assertions and isolation checks.
7. Add production exclusion scanner, contract drift manifest and Chinese workflow/extension guidance.
8. In the actual checkout: generate/inspect the minimal npm lock delta, then invoke the designated
   Luna xhigh acceptance task for targeted tests, build and browser checks. Do not push/open PR yet.

## Review focus

Late responses after reset; wrong-viewer writes; persistent or missing capability results; requests
escaping an inactive worker; retries consuming scenario sequence; stale state after auth changes;
localhost cookie contamination; mock fixture drift from real parsers; accidental production assets.

## Verification boundary

Writing test files is not passing tests. Syntax/package integrity checks are not runtime acceptance.
Real Django Session/CSRF, private content ACL and Miniflux/provider behavior retain separate tests.
