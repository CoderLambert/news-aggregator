## 本批已实现（针对 Issue #55 / #52）

### F55-R1 — 来源标题的安全辅助归组

- 主题未知的新来源在**个人主动发起的规则预览**中，分析最近最多 12 篇不同的已入库文章标题；至少 3 篇不同标题且一个主题匹配至少一半标题，才给出最多 3 个低置信度建议。
- 标题重复、同一标题关键词重复均不增加信心；仅采用极窄的中英文词汇规则，拒绝宽泛关键词。
- 返回 `origin=title_evidence`、`needs_review=true` 和可读证据数量。没有匹配则仍标记“信息不足”；不修改全站 SourceTopicProfile，不自动订阅，不在 `off/suggest/auto` 的新订阅热路径里使用低置信度主题。
- 之前由管理员人工清空的主题保持优先，不被推测重写；AI 分类仍为独立的需授权能力。
- 若标题发生变化，针对推测结果的旧预览提交返回 409，不能以过期依据落库。
- 前端新增“标题证据推测·待确认”标签，主题预设按钮提供 `aria-pressed` 状态。
- 后端新增六项回归（3 纯算法、3 规则/API/自动分组），前端新增 1 项预览确认测试。

### F52-R2 — 来源探测的响应上限

- `probe_source` 现在只读取配置的 `max_response_bytes + 1` 字节，并在解析任何 HTML/RSS/JSON 之前拒绝超限响应。
- 拒绝原因使用稳定的 `response_too_large` 代码；不上传原始正文/令牌，也不修改审批和启用流程。
- 新增 1 项 API 级离线回归，证明超大 Feed 不被解析且目标不被启用。
