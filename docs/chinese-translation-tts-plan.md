# 英文文章中文语音方案

## 目标

英文文章支持两种明确的朗读方式：

- **中文译文（推荐）**：使用当前用户可见的中文译文和中文音色。
- **英文原文**：使用原文和英文音色。

文章的页面显示模式与朗读语言彼此独立。用户请求中文朗读时，系统不会把英文正文交给中文音色，也不会静默退回英文。

## 第一阶段交互

文章页的耳机按钮打开朗读设置，用户选择朗读语言和范围（摘要/全文）后开始播放。

- 中文译文已存在：直接生成并播放中文音频。
- 中文全文缺失、英文全文存在：提供“翻译全文并播放”。只有用户点击后才发起翻译，翻译完成后自动播放。
- 英文全文缺失：提示先获取原文。
- 翻译正在运行：复用现有任务并等待结果，不重复创建翻译请求。

全局播放器显示当前语言和朗读范围，并保留倍速、音色、暂停、继续、停止和重试功能。

## API

`GET /api/news/:id/tts/?language=zh|original&scope=summary|full&voice=...`

旧的 `displayMode` 参数继续兼容：`original` 映射为原文，其余值映射为中文。

安全错误只返回稳定代码与中文提示：

- `translation_required`：当前用户没有可用中文译文。
- `source_content_required`：所选范围没有原文内容。
- `unsupported_language` / `unsupported_scope`：参数无效。
- `tts_unavailable`：语音服务暂不可用。

## 译文与缓存边界

中文全文解析规则与新闻详情接口一致：

1. 用户存在当前启用的 ChatGPT 订阅连接时，只读取该用户、该连接、该新闻且原文哈希一致的私有译文。
2. 该私有译文缺失时不回退到共享译文，避免跨连接或跨用户泄漏。
3. 用户没有启用订阅连接时，读取新闻记录中的共享译文。

缓存键由新闻 ID、朗读语言、范围、音色、译文命名空间和实际朗读文本哈希共同生成。译文更新后自动使用新缓存；私有译文之间不会共用缓存。

## 验收标准

- 英文文章可以分别播放中文译文和英文原文。
- 中文全文缺失时，只有用户主动点击才发起翻译，并在完成后自动播放。
- 请求中文时不会播放英文替代内容。
- 当前用户的私有译文可用于语音，其他用户和匿名用户不能访问。
- 摘要与全文严格对应所选范围。
- Docker 环境能够生成音频，重复请求命中按内容版本隔离的缓存。

## 后续阶段

第二阶段可增加双语逐段交替朗读。该模式需要段落对齐、双音色切换和统一进度映射，本阶段不包含，避免把整篇中文和英文简单拼接造成过长音频与差体验。
