# 独立共享译文与用户私有译文

## 目标与决策

同一篇公开新闻首次完整翻译后，复制一份到独立的站点共享存储。后续读者复用译文，不再次调用模型。ChatGPT 连接、Token 与个人重翻结果仍按用户隔离。

采用同一数据库中的独立表，不额外部署存储服务：

| 数据 | 用途 |
| --- | --- |
| `ChatGPTArticleTranslation` | 当前用户、当前订阅连接的私有译文 |
| `SharedArticleTranslation` | 仅保存完整的公开文章译文，不关联用户或连接 |
| `SharedArticleTranslationTask` | 数据库任务认领、租约、超时恢复，不保存凭据 |

共享缓存按文章、原文 SHA-256、目标语言、翻译提示版本识别。模型与提供方只作为来源信息，不构成缓存键，因此不同模型可以复用同一份公共译文。

## 使用流程

1. 普通请求先读当前账号匹配原文的私有译文，再读共享译文。
2. 两者都没有时，认领共享任务；其他读者等待同一个任务完成，不调用自己的模型。
3. 只有完整响应成功、内容非空、原文仍未变化，才保存并发布。流式片段不发布。
4. 发布独立副本，首个有效结果生效。普通翻译不能覆盖已有公共译文。
5. 用户明确重新翻译时使用当前订阅账号，保存自己的版本；已有共享结果保持不变。

第一位发起生成的用户承担这次订阅用量。其他用户的复用只读取数据库，不借用首位用户的凭据。取消观看仅断开本人的 SSE；撤销订阅或切换账号使原任务失效，等待者可重试。

## 数据与失败边界

- 公共结果没有生成者邮箱、用户 ID、OAuth 连接或 Token；公开接口只返回译文及来源/范围。
- 删除生成者或其订阅连接不会删除已发布的公共副本。
- 原文改变后旧哈希自然不命中；旧任务不能把旧译文发布成新版本。
- 唯一约束和原子认领防止多个进程重复生成；租约心跳、最大运行时限、令牌校验防止死锁和过期任务迟到写入。
- 失败不发布、不将部分结果当成完整译文；租约过期后允许新请求接管。
- 历史私有结果和 `News.full_content_zh` 不批量公开导入。旧字段作为兼容读取保留，新共享结果写独立表。
- 公共译文管理员刷新入口暂不包含在本次实现中。

## 实施状态

2026-10-10：已实现。迁移 `0026_shared_article_translations` 新增两个独立表，不迁移历史文本、不变更用户凭据。

| 位置 | 职责 |

| `backend/api/models.py` | 公共副本与租约任务模型，分别有缓存键唯一约束 |
| `backend/api/services/shared_translations.py` | 认领、90 秒租约、20 秒心跳、30 分钟上限、原文校验、首个成功副本、等待 SSE |
| `backend/api/services/chatgpt_subscription.py` | 同一事务校验账号 generation，保存私有结果并发布独立副本 |
| `backend/api/services/chatgpt_subscription_jobs.py` | 个人流式输出、后台生成与租约心跳 |
| `backend/api/views.py` / `subscription_views.py` | 优先复用结果；无公共结果时认领或等待任务 |
| `backend/api/serializers.py` / `services/tts_service.py` | 详情和朗读使用相同的私有优先、公共回退规则 |
| `frontend/src/hooks/useTranslation.ts` | 等待共享结果、更新来源与显示范围、保留用户切换隔离 |
| `frontend/src/components/news-detail/FullContentSection.tsx` | 标注共享/个人译文、等待状态、个人重翻额度说明 |

详情与完成 SSE 新增 `full_content_zh_scope`（`private` / `shared` / `legacy`）；详情还返回 `full_translation_personal_available`。等待事件 `waiting_shared` 不包含任何生成者信息或私有片段。普通读取共享结果不要求订阅仍有效，也不会为读取者创建伪造的个人翻译记录。

ChatGPT 以 `response.completed` 判定模型响应完成；服务端 API Key 路径要求 `finish_reason=stop`，截断/断流后不拼接另一个提供方的文本，也不发布部分译文。新的服务端翻译不再把进度写到 `News.full_content_zh`。已有公共结果时，服务端 API Key 请求（包括 `force`）直接复用；个人重翻需可用的个人订阅连接。

本轮后端 API 回归 251 项、前端 377 项通过；类型检查、Lint、构建通过。新增验证覆盖跨用户单次调用、完整结果发布、失败不发布、账号撤销、原文变化、个人重翻、朗读一致性、删除生成者后的公共副本保留和过期任务接管。验证使用模拟模型响应，不消耗真实订阅额度。

收尾增加中文来源链接抓取期间原文变化的用例，返回 SSE 错误而非 HTTP 500；共享、授权、断线续接定向回归共 66 项通过（含 17 个共享用例）。断线续接测试用事件控制任务完成，避免依赖短暂 sleep 的不稳定时序。本地已备份 SQLite、应用迁移、构建前端并重启 app；健康检查与新闻接口正常，新范围字段已生效。

首次生成失败后的“重试”继续走普通共享任务去重；已有完整译文的重新生成才进入个人重翻。新增两个页面交互用例验证这一区别，页面定向 8 项、翻译 Hook/组件定向 23 项通过。

## 运行限制

- 有效租约内普通请求只认领一个生成任务；个人强制重翻是明确的新模型调用。进程崩溃或网络失败后的重试仍可能再次消耗额度，不能保证供应商侧恰好一次计费。
- 后台任务与个人流式进度仍在进程中，重启后依靠数据库租约过期恢复；完整公共结果持久化，不受重启影响。
- 共享等待 SSE 占用一个 WSGI 请求线程。当前 Waitress 默认 4 线程，多用户部署需按并发量设置 `WAITRESS_THREADS`，更高并发可再改为异步 SSE 或短轮询。
