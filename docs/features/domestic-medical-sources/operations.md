# 国内医疗来源停用与回滚

## 首选停用步骤

1. 在超级管理员控制台对目标来源执行“停用”。
2. 如果任务正在运行，先在现有运行历史区请求取消，等待 Worker 进入终态，再停用。
3. 确认 `CrawlerTarget.enabled=false`，且下一个调度批次不再包含该 `source_key`。
4. 保留 `SourceConfig`、`SourceEndpoint`、`FeedState`、`CrawlRun`、`NewsSourceItem` 和 `News`，不删除历史证据。

重新探测或修改网络/解析配置都会自动关闭调度，但运维人员仍应检查运行中任务的终态。

## 配置回滚

- 管理界面不做就地降版。要恢复旧配置，使用“复制”创建新草稿，重新探测和审批。
- 每次修改会增加 `config_version`；旧任务继续使用自身快照，不会被新配置改写。
- 如果新规则产生错误文章，先停用来源，再按 `source_key` 和运行批次审核受影响的 `NewsSourceItem`；不执行全库删除。

## 应用与迁移回滚

1. 先停止 Crawler Worker 和调度器，保留数据库备份。
2. 将应用回滚到本功能之前的版本。旧应用不会调度不在代码注册表中的动态 `source_key`。
3. 默认保留 0048–0051 表和数据；这是可恢复且不会自动调度的回滚方式。
4. 只在已验证备份、已停止所有新版应用且确定不再需要运行快照后，才可按 Django 迁移顺序回退。

0051 的反向迁移是 no-op，避免在回滚时误删已经关联文章、订阅或运行历史的来源。如确实要删除空草稿，应使用管理 API 的受守卫删除流程。
