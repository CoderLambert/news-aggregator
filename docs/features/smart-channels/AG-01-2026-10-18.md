## 已确认的问题及修复

1. 旧目录规则只按 Source 名称赋可信主题，未核对 Source URL 是否对应白名单发布域名。现在要求 URL 为 HTTP(S)、无 URL 用户信息、主机名精确命中现有经审核策略域名；不做 DNS/网络解析。冒名来源退为无可信规则主题。
2. 旧 evidence hash 未绑定网站、简介、语言、地区、来源类型、刊物展示名及相关阅读策略。现在有独立的证据 schema version 2 并纳入这些公共身份字段、主题字典版本与策略契约版本。来源发生变化时历史提案的证据哈希失效；不包含私人订阅数据。
3. 旧手工资料在来源身份变化后仍被当作高可信数据自动归组。现在保留人工内容与修订历史，但标记 `metadata_status=stale_manual`、`needs_review=true`，阻止新增订阅直接自动归组；管理员提交同一内容可重新确认新身份。
4. 公共目录与详情增加向后兼容的 `taxonomy_version`、`evidence_version`、`metadata_status` 字段。GET 没有网络/模型调用，不写 SourceTopicProfile。来源重算仍由既有 Worker/服务显式执行，重复运行不改变未变化的 revision。

## 合同边界

- `metadata_status=trusted` 仅表示当前来源主题有经审核静态规则或当前人工资料的元信息证据，并不表示内容真实性、出版社签名验证或可自动订阅。
- `metadata_status=needs_review`、`stale_manual` 不授权自动归组；用户手工预览/确认继续有效。
- 不覆盖私人分组，不自动订阅，不将历史 AI 低证据主题升级为可信。
- 未修改 schema，原 0043 迁移保留。版本化证据通过显式 `refresh_profiles` 幂等重算；不在 GET 里自动迁移。
- 不接触真实模型、生产抓取、生产数据库。
- 覆盖用例：`backend/api/tests/test_ag01_source_metadata.py` 与既有 `test_smart_channel_workspace.py`。
