# BYOK Test 与验收证明（待拆分）

本目录用于后续按 Task ID 关联测试契约、变更前基线、回归证据与真实 API 联调记录；**此处目前不是 BYOK 业务测试通过报告**。

核心准则：
- 变更前旧测试通过，修改后失败且需求未变：修实现，不调整断言迁就代码。
- 基线与分支均失败：调查既有缺陷、波动和环境问题，不冒充新回归。
- 需求明确改变行为：记录变更依据，保留不应改变的旧功能约束。
- 只读 GET 恢复不得产生任何 Provider 调用；跨用户数据/Key/任务不可混用。
- SSE EOF 不代表成功；真实上游终态及结果事务保存均成立才能确认完成。
- 六家厂商通用 API 的真实联调未执行时，记录 `NOT_RUN`，不使用 mock 冒充验证通过。

静态原型可独立执行 [check_ui.py](../prototype/check_ui.py)，只验证模拟交互，不构成业务测试证据。
