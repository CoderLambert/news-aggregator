## 1. 信息架构

既有 `/settings` 保留阅读偏好和 ChatGPT 订阅。增加独立入口「AI 模型与密钥」，路由 `/settings/ai`。在 `/settings` 的账号与连接区展示两个并列但独立的入口：

1. **AI API Key** → `/settings/ai`：用户自行支付服务商 API 费用，Key 由本站业务后端加密托管，并按用户请求经受信共享 Proxy 转发；可为四类任务选择模型。
2. **ChatGPT 订阅** → `/settings/chatgpt`：保留原页面、原权限和独立门禁，不作为 BYOK 隐式兜底。

新页面分为三个导航区域。前两个是实装工作页面，第三个是交互设计中的集成展示，正式开发将相关控件嵌入既有文章页，而非发布独立预览路由。

| 区域 | 页面目的 | 操作 |
|---|---|---|
| 模型与用途 | 全局默认 + 问答、翻译、研究、问题推荐四类配置 | 选择、保存、撤销尚未保存修改 |
| 服务商连接 | 管理官方 Key 与模型目录 | 添加、替换、显式测试、添加模型、删除 |
| 文章内体验预览 | 解释具体任务中如何选模型 | 仅演示切换与任务创建前预选，不建立真实任务 |

## 2. 关键流程

### 初次使用

空账户状态 → 选择首批 6 个产品预设之一 → 填写服务商、地域、连接别名、Key → **保存连接（不主动测试）** → 添加模型 ID → 明确选择模型用途 → 保存 → 回到文章页面调用 AI。六个预设是首批产品范围，不限制未来 LiteLLM Proxy 可支持的 provider。

**注意：连接创建与验证是两项独立操作。** 模型列表可从预置目录选取或手工添加 ID；不假设所有厂商都提供同一种可枚举模型列表 API。

### 多个 Key 与模型

同一家厂商可有多个连接。模型选择使用 `connection_id + model_id`，不能仅依赖模型名称，也不能隐式在同名连接之间切换。链接展示服务商、地域、别名、验证状态。Key 永不回显。

### 测试、验证与禁用

保留明确的 UI 区分：`Key 已保存 / 未测试 / 最近一次测试成功 / 最近一次测试失败 / Key 已撤销`。模型能力还应单独显示：`未验证 / 文本已验证 / 工具调用已验证 / 不兼容`。连接成功不证明模型具有研究需要的工具调用能力。真实测试按钮经业务后端和共享 Proxy 发出，并明示会把测试输入发送给所选厂商且可能产生少量费用；页面和浏览器不会直接将用户 Key 发往 Proxy 或厂商。

### 任务偏好

设置页保存偏好是显式操作，不因为添加连接自动替换默认模型。已有任务冻结执行配置，改默认值只影响新任务。

- 新闻问答：可在每次新提问前选择“本次使用”模型；本次覆盖不修改全局保存值。
- 全文翻译：创建任务时固定连接、模型、文章快照，优先复用同一来源的已保存个人译文；不隐式重复发起付费生成。
- 深度研究：创建新研究会话前选择；会话运行期间不跨厂商切模型；研究按钮应要求服务端实际确认工具能力。
- 问题推荐：只有明确点击“生成/换一批”才使用选中模型；页面加载只读已有缓存或显示静态建议。

### Key 替换或删除

替换凭据使连接的服务端 `credential_epoch` 增加。用户 provider Key 与 Proxy 项目 virtual key 属于不同凭据：业务后端在授权操作中按请求显式将个人 Key 传给受信 Proxy；每个业务项目另用独立且受限的 virtual key。Proxy master key 仅用于隔离的运维流程，不进入业务运行容器。旧授权无法通过新任务检查；任务执行权和数据库提交另行检查。删除连接后，相关偏好失效并提醒重新选择，**不回退到部署 Key、平台 Key、其它用户 Key 或订阅凭据**；历史私人结果继续可读。若仍有活跃任务，应显示服务端实际处理状态。

## 4. 必须覆盖的状态与限制

- 未登录或服务端 BYOK 功能关闭：不给出可提交的 Key 输入；显示登录 / 能力状态。
- 空账户：提示按步骤添加连接、模型和用途。
- 保存请求 pending / failed：保留草稿，不假报成功。
- 切换账号：旧查询、输入内容和异步结果不能出现在新账号下。
- Key 已保存但无模型：不可选择 AI 功能模型。
- 模型 ID 未验证：提示风险；研究工具调用必须经过能力校验。
- 删除关联连接：显示显式确认及其影响，清理悬空偏好，不复活旧 Key。
- 服务端凭据错误：隐藏原始响应和敏感 Key，仅返回安全可读错误。
- 实际服务端回包或 SDK 变更：终态由 Proxy 原始事件与业务后端完整性校验共同确认，不由 UI 根据 SSE 断线猜测。
- 官网地域：只用端点白名单，不让普通用户写任意 URL。
- 业务请求只允许受信端点、模型别名和已审核凭据字段白名单；不得从用户传入 `user_config`、`api_base`、任意 headers、callback 或 Proxy 路由/fallback 配置。出站网络需阻断私网与云元数据地址。
- 文章正文与问题的接收方包括业务后端、共享 Proxy 和用户所选服务商；不记录在日志/回调中。首版关闭跨租户共享内容缓存。
- 共享 Proxy 有独立配置、Postgres 和生命周期，不由 NewsHub Web/Worker 启动。生产代理缺失或不可达时明确失败关闭，不直连 provider；新闻阅读和已保存历史不受影响。
- 审计 / 用量：首版只显示真实持久数据；没有数据时显示“暂无记录”，不能伪装为零费用。
- 可访问性：可聚焦按钮、键盘关闭模态框、清晰的按钮文案、错误状态可见，触控目标推荐 ≥ 44px。

## 5. 原型说明

HTML 是**纯前端交互原型**，用演示数据预置 DeepSeek、百炼和几个模型。所有测试、保存、删除与问答结果都是浏览器内模拟；不接 LiteLLM Proxy、不验证凭据隔离、路由或 provider 兼容，不做持久化。请不要输入真实 API Key。

体验顺序：

1. 打开页面，查看四个功能模型分配和保存机制。
2. 切换“服务商连接”，打开 6 家中的任意一家，填写示例字符串保存。
3. 点击新增连接的“添加模型”，填写样例模型 ID。
4. 返回“模型与用途”设置新模型，保存。
5. 查看“文章内体验预览”，切换本次模型并展示模拟答复。
6. 点击右上角“查看空账户状态”，核对首次使用体验。

页面设计方向已获确认；业务编码从 `feat/byok-user-api-keys` 的实际当前 HEAD 开始，每次实施前核对远端 HEAD 与回归基线。
